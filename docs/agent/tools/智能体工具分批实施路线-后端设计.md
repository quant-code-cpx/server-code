> 状态：五批代码均已实现；第四批按外部数据门禁部分启用，第五批已通过本地真库验收

## 1. 目的

把未开放的数据和计算能力固化为可追踪批次。每批拥有独立契约、代码边界、测试、发布和回滚，不依赖后续重新调研，也不要求一次全部实现。

Tool 按用户研究意图组织，不按 138 张表逐表暴露。模型始终不能访问 Prisma、SQL、Tushare、文件系统或任意 URL。

## 4. P1.0 前置：能力目录与 Tool 预选

### 4.1 原因

当前 `PlanNode` 会把 Workflow allowlist 中全部启用 Tool Schema 放进规划提示。Tool 增至 25–35 个后，提示体积、选错 Tool 和无关调用风险都会上升。

第二批随 Workflow v6 增加两阶段选择：

```text
LoadContext
  -> SelectToolsNode：只看短目录，选择能力包和最多 18 个 key
  -> PlanNode：只接收所选 key 的完整 JSON Schema
  -> AuthorizeTools
  -> ExecuteTools
```

### 4.2 固定能力包

| pack key             | 内容                                 |
| -------------------- | ------------------------------------ |
| `CORE_RESEARCH`      | 证券解析、行情、概要、数据可用性     |
| `STOCK_FINANCIAL`    | 财务三表、财务指标、估值、资金流     |
| `STOCK_TECHNICAL`    | 技术指标、标准信号、筛选             |
| `STOCK_DEEP`         | 筹码、两融、相对强弱、事件、股东     |
| `MARKET_MULTI_ASSET` | 市场、指数、基金、行业、因子、宏观   |
| `EXTERNAL_EVENT`     | 搜索、网页正文、结构化事件、事件研究 |
| `DERIVATIVES`        | 期权、可转债                         |
| `PRIVATE_ANALYTICS`  | 自选、组合、回测、报告               |

### 4.3 目录结构

新增 `ToolCapabilityCatalogService`，每项只暴露：

```ts
interface ToolCapabilityDescriptor {
  key: AgentToolKey
  latestVersion: number
  pack: ToolCapabilityPackKey
  purpose: string
  positiveExamples: string[]
  negativeExamples: string[]
  requiresSecurityTypes: Array<'STOCK' | 'INDEX' | 'FUND' | 'OPTION' | 'CONVERTIBLE_BOND'>
  dataScope: 'PUBLIC' | 'USER_PRIVATE' | 'PUBLIC_WEB'
  costClass: 'LOW' | 'MEDIUM' | 'HIGH'
}
```

`SelectToolsNode` 结构化输出：

```json
{
  "packs": ["CORE_RESEARCH", "STOCK_DEEP"],
  "toolKeys": ["resolve_security", "get_stock_events"],
  "reason": "查询指定股票近期公司事件"
}
```

约束：

- `packs` 1–3 个，`toolKeys` 1–18 个，必须来自冻结目录。
- 自动补齐依赖，例如任何证券 Tool 自动加入 `resolve_security`；解释无数据时加入 `get_data_availability`。
- 最终 key 必须同时满足生产 enabled、Workflow allowlist、能力包选择和用户权限。
- 选择失败时 fail closed，回退 `CORE_RESEARCH`，不能暴露所有 Tool。
- 目录版本、选择模型、Prompt 版本、选择结果和 hash 写入 Run 审计。
- v1–v5 Workflow 不改；v6 起增加 `select_tools` 节点。

## 5. 全批次共同不变量

### 5.1 数据边界

- Agent Tool 只调用领域 Facade，不调用 Controller。
- 本地已有数据时只读 PostgreSQL，不在用户请求中触发 Tushare 同步。
- 缺数据返回 typed error 和水位线，不在线补数。
- 动态表名、列名、因子表达式、URL 和 SQL 不接受模型输入。
- 任何本地估算必须显式 opt-in，输出 `isEstimated=true` 和算法版本。

### 5.2 时间与来源

- Agent Tool 日期统一 ISO `YYYY-MM-DD`；Facade 内部转换 `YYYYMMDD`。
- 输出同时包含 `requestedAsOfDate`、`dataThrough`、`coverageStart`。
- 财务、事件、股东按公告可得日过滤；没有公告日的数据必须 warning，不能伪装成点时可得。
- 数值保留真实单位、币种、复权、算法和数据版本；数据库 null 原样返回 null。
- ToolResult 统一使用现有 provenance、warnings、truncated、nextCursor 和 audit ID。

### 5.3 权限与副作用

- 公共数据：`USER + READ + PUBLIC_MARKET_DATA`。
- 联网数据：`USER + READ + PUBLIC_WEB`，保留 SSRF、URL token、引用和 Prompt Injection 标记。
- 用户数据：强制从 `ToolAccessContext.userId` 取 owner，不接受模型传 userId。
- 写 Tool 默认禁用；启用后仍需确认 token、内容 hash、幂等键和审计。
- 持仓修改、通知渠道、定时任务不作为模型自由 Tool。

### 5.4 结果与成本

- 单 Tool 最大结果行数写入 Schema 和 Policy，Repository 查询再次限界。
- 大序列分页或确定性采样，不静默截断。
- 高成本计算一次 Run 最多 3 个，受现有 `AGENT_MAX_TOOL_CALLS` 和成本预算共同限制。
- 每个新查询上线前保存 `EXPLAIN (ANALYZE, BUFFERS)` 证据。
- 不增加重复索引；只有现有索引不能支撑稳定查询时才创建 migration。

## 7. 每批统一交付物

每批必须同时提交：

1. canonical key、Tool Definition、输入/输出 JSON Schema。
2. feature Module、Facade、Repository 或计算 Service。
3. Registry、AgentModule、Workflow、能力目录和 Prompt 路由。
4. schema export 和前端合同。
5. 独立业务推导的单元测试、Adapter 契约测试、Workflow 路由测试。
6. 真实 PostgreSQL 黑盒测试和性能证据。
7. 指标、日志、Grafana/告警更新。
8. `AGENT_TOOLS_ENABLED` 灰度、回滚和历史 pin 验证。
9. 文档状态与 `docs/README.md` 更新。

## 8. 批次准入门禁

Tool 进入生产 enabled 前必须全部为 PASS：

| 门禁 | 标准                                                   |
| ---- | ------------------------------------------------------ |
| 数据 | 非空、覆盖范围明确、最新水位线达标、核心字段非空率达标 |
| 服务 | Facade 无上游直连、无 catch-all 吞错、无动态 SQL 输入  |
| 契约 | Schema 严格、错误 typed、单位/时点/来源完整            |
| 权限 | 公共/私有/联网隔离，owner scope 有越权测试             |
| 路由 | 正例、反例、跨域问题和失败恢复均通过                   |
| 性能 | P95 达标、结果上限有效、查询计划可接受                 |
| 运行 | build、相关 Jest、真实库、容器日志通过                 |
| 回滚 | 移除 enabled key、回切 Workflow 后历史 Run 可重放      |

若数据为空或上游权限未确认，只保留设计和同步任务，不注册空壳 Tool。

## 9. 发布节奏

不绑定日历日期。执行原则：

1. 一次只实施一个批次。
2. 前一批完成真实问题验收并稳定观察后，再启用下一批。
3. 每批可先合并代码但保持 disabled，灰度通过后再改生产 allowlist。
4. 某批被阻塞不影响后续无依赖批次开发；但生产启用仍按 Workflow 版本依赖顺序。

## 10. 最终能力闭环

五批完成后覆盖：

```text
证券解析
  -> 价格/估值/财务/资金
  -> 技术指标/标准信号
  -> 筹码/两融/相对强弱/事件/股东
  -> 指数/基金/行业/因子/宏观
  -> 联网证据/期权/转债/事件研究
  -> 回测诊断/组合分析/报告确认保存
```

仍不开放：通用 SQL、任意代码、任意因子表达式写入、无确认交易、无确认持仓修改、无确认通知和无审计网页写入。
