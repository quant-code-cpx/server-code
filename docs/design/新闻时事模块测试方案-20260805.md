## 4. 业务模型与独立 Oracle

### 4.1 核心业务场景

1. 用户查询最新市场快讯、公告、指定证券、自选股和组合相关消息。
2. 用户能看见来源、发布时间精度、首次发现时间、数据水位和覆盖缺口。
3. Scheduler/管理员触发采集；Worker 在重复轮询、部分坏行、并发和上游故障下保持幂等。
4. 同一文章内容变化时新建不可变修订，不能覆盖历史。
5. Agent 先读本地新闻；高风险、无 URL、冲突或“最新”事实按权限走受控搜索与引用。

| R-006 | 只允许 http/https；移除 fragment、默认端口和已知跟踪参数，保留未知业务参数                 | §7.2            |
| R-007 | identity 优先 URL；无 URL 使用稳定 provider/upstreamId；最后才生成 synthetic ID            | §7.3            |

| R-019 | `UNKNOWN` 只在 `includeUnknownPublishedTime=true` 时返回                                   | §10.1           |

### 4.3 状态与不变量

| 对象         | 合法状态/变化                                          | 不变量                                         |
| ------------ | ------------------------------------------------------ | ---------------------------------------------- |
| IngestionRun | QUEUED → RUNNING → SUCCEEDED/PARTIAL/FAILED/CANCELLED  | 完成态不可回到 RUNNING；计数非负且守恒         |
| Article      | 首次建文；identity 永久稳定；current revision 单调递增 | 同 identity 仅一篇；历史 revision 不更新/删除  |
| ProviderItem | firstSeen 固定，lastSeen/retrievedAt 可推进            | `(provider,feed,upstreamId)` 唯一              |
| Cursor       | CAS version 单调递增                                   | 失败/取消/Schema 漂移不推进                    |
| Circuit      | CLOSED → OPEN → HALF_OPEN → CLOSED/OPEN                | HALF_OPEN 只允许一个探测请求                   |
| Quarantine   | 创建 → 可重试 → resolved                               | 脱敏；同 Run+item 不重复；修复后最多建一篇文章 |
