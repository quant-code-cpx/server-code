## 3. 业务理解

### 3.1 业务场景

1. 用户创建会话并提问，系统原子创建用户消息、assistant 占位消息、Run、初始事件和可靠投递意图。
2. Worker 领取 Run，按冻结的 workflow/prompt/model/tool policy 执行受控研究。
3. 模型只能选择 allowlist 内 Tool；证券、用户资源、日期、预算和参数由服务端再次验证。
4. Tool 返回带来源、数据时点、单位、复权、算法版本和 warning 的事实包；模型不得编造缺失数字。
5. Run 的消息、步骤、Tool/模型调用、来源、引用和事件先持久化，再通过 POST-SSE 重放/实时返回。
6. 前端按 sequence 幂等消费，刷新或断线后恢复；只渲染白名单内容块。
7. 用户可取消、继续追问和重新生成；历史消息、引用和版本不能被覆盖。

### 3.2 核心业务规则

| 规则编号 | 规则                                                                            | 来源                | 测试影响                                                |
| -------- | ------------------------------------------------------------------------------- | ------------------- | ------------------------------------------------------- |
| R-001    | 用户身份只来自 JWT，Body/模型不能提交或覆盖 `userId`                            | 安全设计、REST 协议 | 未登录、跨租户、未知字段和 prompt 注入必须失败          |
| R-002    | `clientRequestId` 对用户唯一；相同请求幂等，不同内容冲突                        | REST 协议           | 顺序和并发重复请求不能创建第二个 Run                    |
| R-003    | Run 状态只按 `QUEUED→RUNNING→终态` 或取消路径转换，状态与事件同事务             | 状态模型            | 非法回退、取消竞态、终态复写必须失败                    |
| R-004    | 同一 Run 的持久事件 sequence 从 1 严格递增、唯一；终态是最后业务事件            | SSE 协议            | 重放、live tail、重复/gap/终态测试                      |
| R-005    | 断线不终止 Run；客户端从连续 sequence 或同 Run `Last-Event-ID` 恢复             | SSE 协议            | 刷新、断网、重复连接不得丢失或重复业务状态              |
| R-006    | Tool 默认 deny，只能调用已注册、已授权且输入/输出 Schema 合法的版本             | Tool 标准           | 未注册、越权、超限、畸形输入/输出必须 typed failure     |
| R-007    | 用户私有 Tool 的 `userId` 不出现在模型 Schema，Facade 再校验资源归属            | Tool Schema         | 组合、回测、自选跨租户不可枚举资源存在性                |
| R-008    | 数据事实必须带真实 `asOf`、来源、单位/比例 scale、复权和 warning；`null` 不转 0 | 内容块/Tool 协议    | 金融 golden、空值、过期数据和 provenance 测试           |
| R-009    | 财务历史研究按公告可用时点过滤；报告期、公告日、可用日不得折叠                  | 个股工作流          | 禁止公告日前视，修订不可恢复必须 warning/fail-closed    |
| R-010    | 确定性量化结果按固定算法版本计算；数值断言来自手算/独立公式                     | 量化 Tool Schema    | 总收益、波动、Sharpe、回撤、估值分位必须精确            |
| R-011    | 搜索摘要不能作为关键事实引用；网页必须经签名 URL token 抓取和 hash 绑定         | 联网 Tool Schema    | 抓取失败时不能伪造引用或把 snippet 当已核验事实         |
| R-012    | 网页、用户输入和模型输出均不可信，不能升级权限、执行 SQL/脚本或调用禁用 Tool    | 安全设计            | prompt injection、SSRF、XSS、任意 Tool/URL 请求必须无效 |
| R-013    | assistant 只有在消息内容块、引用覆盖、审计链和终态事件全部提交后才可 COMPLETED  | 工作流设计          | 任一关键审计写失败不得产生成功终态                      |
| R-014    | 取消后迟到结果可审计，但不能把 Run/Message 改回 COMPLETED                       | 状态模型            | Tool 完成与 cancel race 以服务端 CAS/终态为准           |
| R-015    | 预算、次数、超时、并发和结果大小达到上限时受控失败/部分结果，不隐式超支         | 工作流/安全设计     | 配额和压力场景必须可预测，不得无限重试                  |

### 3.3 状态变化与不变量

| 类型            | 说明                                                                                                              |
| --------------- | ----------------------------------------------------------------------------------------------------------------- |
| 数据写入        | 会话、用户消息、assistant 版本、Run、Step、ToolCall、ModelCall、Source、Citation、Event 可按 runId 串成完整审计链 |
| 缓存/队列/通知  | Redis/BullMQ 只负责投递与租约；PostgreSQL 是权威状态；Redis 短暂失败不能丢命令意图                                |
| 权限边界        | 会话、Run、消息、Tool 摘要和 SSE 均按当前 userId 所有权过滤；越权统一不泄露资源存在性                             |
| 时间/交易日规则 | 公共日期为 ISO；“今天”按 Asia/Shanghai；请求日与真实数据日分别记录；非交易日不得伪装成交易日                      |
| 数据不变量      | `null ≠ 0`；百分数/小数 scale 明确；K 线升序且 OHLC 关系合法；财报 PIT；引用属于同一 Run/用户                     |
