## 3. 业务理解

### 3.1 业务场景

- 内部摘要任务提交结构化摘要结果；Service 计算内容 hash，Repository 原子推进摘要版本。
- 会话详情只展示当前摘要 metadata，不泄露摘要正文、facts 或内部 source 列表。
- 用户通过记忆管理 API 查看、显式创建、纠错、删除自己的长期记忆。
- 创建和纠错请求必须携带不可省略的 `confirmation=true`，否则不写数据库。

### 3.2 核心业务规则

| 规则编号 | 规则                                                                 | 来源          | 测试影响                              |
| -------- | -------------------------------------------------------------------- | ------------- | ------------------------------------- |
| R-001    | 摘要正文和 facts 不通过公共详情接口暴露                              | Batch 019     | detail 仅返回 metadata                |
| R-002    | 摘要 hash 由服务端对规范化内容计算                                   | 审计要求      | 不信任调用方 hash；相同内容 hash 稳定 |
| R-003    | 用户身份只从 JWT 注入，Body 禁止 `userId`                            | REST/安全设计 | 跨租户和未知字段负例                  |
| R-004    | create/update 必须显式 `confirmation=true`                           | Batch 019     | false、缺失均拒绝                     |
| R-005    | create 对用户表现为单次原子确认                                      | 数据一致性    | 失败不能留下隐藏 candidate            |
| R-006    | update 创建新版本，不原地覆盖历史                                    | ADR-005       | 返回 `version + 1`，旧版保留          |
| R-007    | delete 立即从默认 list 与后续上下文候选中排除                        | Batch 019     | 删除成功后默认列表不可见              |
| R-008    | list 默认只返回 active；`includeInactive=true` 返回未删除历史        | 管理需求      | 状态过滤固定                          |
| R-009    | list 使用稳定 `(updatedAt,id)` cursor，limit 1–100                   | API 稳定性    | 同毫秒无重复遗漏，非法 cursor 400     |
| R-010    | value 为非 null JSON，序列化后最多 8192 bytes、深度最多 8            | 安全/容量     | 超大和过深输入在 DB 前拒绝            |
| R-011    | forbidden topic 始终拒绝；明显敏感 key/value 即使声明 GENERAL 也拒绝 | 记忆策略      | 防止直接分类伪装绕过                  |
| R-012    | DTO、响应和日志不得包含密码/token/隐藏推理/内部 userId               | 安全设计      | 严格 Body 与响应白名单                |

### 3.3 服务与 API 契约

Summary Service：

- `commit(userId, conversationId, input)`：规范化摘要 payload、计算 SHA-256、调用 Repository CAS 提交。
- `currentMetadata(userId, conversationId)`：返回 current metadata 或 `null`；不返回 `summaryText/facts/sourceMessageIds`。

Memory API：

| 接口                         | Body                                                                                      | 成功响应                          |
| ---------------------------- | ----------------------------------------------------------------------------------------- | --------------------------------- |
| `POST agent/memories/list`   | `{ cursor, limit, includeInactive }`                                                      | `{ items, nextCursor }`           |
| `POST agent/memories/create` | category/key/value/sensitivity/source IDs/confidence/expiresAt/topic/`confirmation:true`  | Memory DTO                        |
| `POST agent/memories/update` | memoryId/value/可选 sensitivity/source IDs/confidence/expiresAt/topic/`confirmation:true` | 新版本 Memory DTO                 |
| `POST agent/memories/delete` | `{ memoryId }`                                                                            | `{ memoryId, status, deletedAt }` |

所有路径均 `POST('非空路径')`、HTTP 200 成功、`@StrictAgentBody`、专用 Swagger response DTO。

### 3.4 Memory 响应白名单

`memoryId/category/key/value/sensitivity/status/sourceConversationId/sourceMessageId/confidence/version/validFrom/confirmedAt/expiresAt/revokedAt/deletedAt/createdAt/updatedAt`。不返回数据库 `userId`、内部错误、日志 payload。

## 4. 错误契约

| 业务码                                | HTTP | 场景                                     |
| ------------------------------------- | ---: | ---------------------------------------- |
| `AI_CONFIRMATION_REQUIRED` / 6030     |  409 | create/update 未显式确认                 |
| `AI_MEMORY_NOT_FOUND` / 6032          |  404 | 记忆不存在或不属于当前用户               |
| `AI_MEMORY_VALIDATION_FAILED` / 6033  |  400 | 策略、来源、value、cursor 或业务参数非法 |
| `AI_MEMORY_CONFLICT` / 6034           |  409 | active key 或版本并发冲突                |
| `AI_SUMMARY_VERSION_CONFLICT` / 6035  |  409 | 内部摘要 expected version 冲突           |
| `AI_SUMMARY_VALIDATION_FAILED` / 6036 |  422 | 内部摘要内容、范围或 Prompt 非法         |

## 6. 风险分析

| 风险                  | 业务影响               | 测试策略                              | 优先级 |
| --------------------- | ---------------------- | ------------------------------------- | ------ |
| Body 可伪造 userId    | 跨租户数据泄露/篡改    | Strict Body + 双用户真实 DB HTTP 测试 | P0     |
| create 半成功         | 请求失败却遗留候选     | 真实事务故障注入、写后计数            | P0     |
| 响应泄露摘要/内部字段 | 隐私与实现细节泄露     | 响应精确 key 断言                     | P0     |
| confirmation 可省略   | 未授权长期记忆         | DTO + Service 双层门禁                | P0     |
| value 无上限          | DB/日志/模型上下文放大 | byte/depth 边界                       | P0     |
| 并发 create/update    | active 重复或历史覆盖  | 双请求竞争、版本和计数断言            | P0     |
