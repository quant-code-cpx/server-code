## 3. 业务理解

### 3.1 业务场景

用户保存“收盘后研究”“每周组合风险复盘”或受限指标条件。系统只有在正确时区的逻辑触发时间、交易日和数据水位都满足时，才创建一次不可重复、可审计的 Agent Run；数据未准备好时应明确延后或跳过，不能读半同步数据或重复计费。

### 3.2 核心业务规则

| 规则编号 | 规则 | 来源 | 测试影响 |
| --- | --- | --- | --- |
| R-001 | Task 只允许 `CRON`、`ONE_TIME`、`STRUCTURED_CONDITION` 及其白名单 JSON | Batch 020 §4/10 | 拒绝代码、SQL、表达式和未知字段 |
| R-002 | `nextRunAt` 由服务端按 IANA timezone 计算；交易日不能用简单周一至周五替代 | Batch 020 §10/18 | DST、节假日、上海时区用例 |
| R-003 | 同一 `(taskId, scheduledFor)` 最多一条 execution | Batch 020 §9/21 | 双 scanner、重复 tick、手动 run 幂等 |
| R-004 | schedule pause/delete 阻止未来执行，不追溯取消已入队或运行中的 Run | 调度架构 §4/6 | pause 竞态、恢复和软删除 |
| R-005 | 数据水位、交易日、额度任一不满足时不得创建 Run；必须保存 defer/skip 证据 | Batch 020 §11/23 | watermarks、配额、原因和重试 |
| R-006 | execution 固定 workflow/prompt/model/tool policy/budget 版本，历史不可改写 | Batch 020 §11/23 | 更新后旧 execution 审计一致 |
| R-007 | owner 只从 JWT 取得；资源归属在创建和执行时复核 | Batch 020 §19 | 跨租户、资源删除、伪造 userId |
| R-008 | scheduler 只入队，不直接调用模型；BullMQ 重复投递由 execution ID 去重 | 调度架构 §2/4 | queue 故障、outbox 恢复、重复 job |

### 3.3 状态变化与不变量

| 类型 | 说明 |
| --- | --- |
| Task | `ACTIVE ↔ PAUSED → DELETED`；版本 CAS 防并发覆盖 |
| Execution | `PENDING → CLAIMED → QUEUED → RUNNING → SUCCEEDED/FAILED/CANCELLED/SKIPPED`；`SKIPPED` 必有原因 |
| 队列 | execution 与 durable queue intent 同一事务；job ID 由 execution ID 导出 |
| 权限 | list/detail/update/pause/resume/delete/run/executions 均 owner-scoped |
| 时点 | `scheduledFor` 是逻辑触发时点；事件在上海交易日与数据截止日上独立判断 |
| 审计 | 每 execution 固定 task 配置快照、gate evidence、Run ID、成本和状态 |

## 4. 接口契约

| 接口 | Body 核心字段 | 预期 |
| --- | --- | --- |
| POST `/api/agent/schedules/create` | trigger、cron/oneTime/condition、timezone、workflow、input、watermarks、budget | 返回 owner-scoped task 和服务端 `nextRunAt` |
| POST `/api/agent/schedules/list/detail` | cursor/limit 或 taskId | 不泄露他人 task/execution |
| POST `/api/agent/schedules/update` | taskId、expectedVersion、可修改配置 | CAS 成功推进版本；历史 execution 不变 |
| POST `/api/agent/schedules/pause/resume/delete` | taskId、expectedVersion | 幂等终态和正确 future scheduling |
| POST `/api/agent/schedules/run` | taskId、clientRequestId | 手动触发仍走 gate、execution 唯一和 queue outbox |
| POST `/api/agent/schedules/executions/list` | taskId、cursor/limit | 返回 execution/gate/Run 摘要，不返回隐藏推理 |

## 6. 风险分析

| 风险 | 业务影响 | 测试策略 | 优先级 |
| --- | --- | --- | --- |
| 多副本重复执行 | 重复收费、重复研究 | DB unique + 双 scanner 并发 | P0 |
| 部分同步数据 | 错误研究结论 | 水位 gate 与 defer evidence | P0 |
| Cron/DST 错算 | 漏报或多次运行 | IANA/DST/one-time 边界 | P1 |
| 跨租户 schedule | 隐私和成本泄露 | owner-scoped API 与执行时复核 | P0 |
| 任意条件表达式 | SQL/代码执行风险 | 严格 DTO 与 allowlist fuzz | P0 |
| queue 故障 | execution 丢失 | outbox/reconcile 恢复 | P0 |
