## 1. 结论与实施决策

当前系统**没有**完整的“个股技术信号历史绩效统计”能力。已有技术指标、择时信号、策略信号历史、事件研究和次日表现统计等零散能力，但尚不能可靠回答以下问题：

- 某只股票近一年、近三年出现过多少次 MACD 金叉等技术信号；
- 信号后第 1、3、5、10、20 个市场交易日上涨、下跌、平盘各占多少；
- 后续收益的平均值、中位数、最大值、最小值、标准差分别是多少；
- 空头信号判断正确的比例是多少；
- 每一个统计样本来自哪一天、使用了什么信号证据、为何被纳入或排除；
- 数据更新或算法升级后，历史结果能否按原口径复现。

需求中的 `mcdn` 在本文、API 和代码中统一更正为 **MACD**；`mcdn` 不作为别名、不进入 DTO，也不进入 Catalog。

采用以下落地决策：

1. 新建独立的 `technical-signal` 领域模块，统一信号语义、样本生成、收益计算与统计，避免继续扩张 `StockAnalysisService`。
2. 完整交付范围固定为单股、日频、按需计算；包含 MACD、KDJ、RSI6、BOLL、MA 多空排列、SAR 翻转、20 日量比状态进入，共 7 个信号族、14 个标准事件。
3. 技术信号一律定义为“状态转换事件”，不把连续多日处于超买/超卖状态重复计数。
4. 信号检测统一使用 `Daily + AdjFactor` 生成的前复权 OHLCV 时间线和本地全精度指标引擎；`StkFactor` 只用于数据对账，不再作为标准信号源。此决策保证 14 个事件使用同一价格口径和同一算法版本。
5. 每次计算从股票首个有效日线加载到 `dataAsOf`，先完成全历史指标递推，再按请求窗口过滤事件；禁止用固定 300 日 warmup 近似 EMA、KDJ、SAR 等路径依赖指标。
6. T+N 指证券所属交易所第 N 个开市日。股票停牌导致目标日无行情时记为缺失样本，不能顺延到该股票下一条行情。
7. 统计同时交付原始收益、方向性收益、沪深 300 基准超额收益、MFE/MAE、均值 95% Student-t 区间和成功率 95% Wilson 区间；这些不是未定义扩展项。
8. 统计摘要与样本明细分开提供；摘要对完整样本聚合，明细独立分页并保留复算证据。
9. 信号定义与《条件订阅规则引擎》共用 `TechnicalSignalDefinitionService`、`semanticsVersion`、`definitionHash` 和 evaluator；标准接口之外的旧接口明确标记为 `legacy.v1`，不与标准结果混算。
10. 本模块不持久化派生指标、事件或统计结果，只使用 Redis 结果缓存。条件订阅拥有的 `TechnicalSignalDailySnapshot` / `TechnicalSignalEvent` 属于订阅执行存储，不改变本模块的按需计算事实源。
11. 默认基准 `000300.SH` 必须完成全历史回补才允许上线超额收益；当前仅约两年的 `IndexDaily` 不视为可用数据基座，不得用空值或降级口径掩盖。

## 2. 需求边界

### 2.1 完整交付范围

- 单只 A 股的近 1 年、近 3 年及自定义日期区间统计；
- MACD、KDJ、RSI6、BOLL、MA 多空排列、SAR 翻转、20 日量比状态进入，共 14 个标准事件；
- T+1/T+3/T+5/T+10/T+20，可由请求指定 1～60；
- 信号发生次数、可到期数、有效数、未到期数、缺失数及缺失原因；
- 原始上涨/下跌/平盘比例和方向性成功率；
- 平均值、中位数、最大值、最小值、样本标准差、P25、P75；
- 沪深 300 基准收益、超额收益及相同分布统计；
- 每个 horizon 的 MFE/MAE、路径覆盖状态、均值 95% Student-t 区间和成功率 95% Wilson 区间；
- 信号样本明细、触发前后证据、目标交易日与收益；
- 数据截止日、信号语义版本、统计版本、收益口径版本；
- 严格的数据就绪校验、Redis 缓存、Swagger 契约、自动化测试与压力验收。

### 2.2 明确不属于本方案

- 不做自动下单、资金曲线、仓位管理和手续费模拟；这些属于回测/交易域。
- 不把技术信号统计解释为投资建议或未来收益预测。
- 不做全市场每日离线预计算、跨股票排行榜或横截面筛选；这些属于全市场信号扫描产品，不是单股统计接口。
- 不做盘中分钟级信号；数据粒度固定为日线。
- 不持久化派生指标、事件或统计结果；算法升级通过版本化重算和 Redis 新 key 生效。
- 不提供 CSV/PDF 文件导出；文件生成由现有 Export/Report 领域负责，本模块只返回结构化数据。
- 不做用户自定义阈值、参数寻优、多信号组合、显著性挖掘或自动选参；这些属于因子研究和回测领域。
- WR、CCI、DMI、TRIX、DMA、BIAS、OBV、VR、EMV、ROC、PSY、BRAR、CR、ATR、HV 固定为指标展示或证据字段，不进入本方案事件 Catalog；本接口不接受这些名称作为 signalKey。

- `000300.SH` 的 `IndexDaily` 当前仅 561 条，覆盖 `2024-04-10` 至 `2026-07-31`。旧版 `MarketSyncService.syncIndexDaily()` 的两年截断已删除；full 模式现从 `19901219` 续传，成功前持续 RUNNING，失败日期入 retry queue，并以 `20050104..dataAsOf` 的 SSE 逐日覆盖检查决定 SUCCESS。真实全历史回补尚未执行前，`includeBenchmark=true` 的功能状态必须为 NOT_READY。
- `trading_signals` 仅 3 条、`event_signals` 0 条、订阅 hit 0 条，不能把现有事件表当作技术信号历史全集。

`INDEX_DAILY` 数据基座的修正规则固定如下：

1. 删除“最近两年”截断，`full` 模式固定从项目最早交易日 `19901219` 扫描到 `targetTradeDate`；指数未成立时 Tushare 返回空集合，不伪造记录。
2. 复用已有 `TushareSyncProgress` 和 `TushareSyncRetryQueue`，不新增表。`mode=full` 且 progress 为 `IDLE/COMPLETED` 时创建新一轮并从 `19901219` 开始；progress 为 `RUNNING` 时必须从 `lastSuccessKey+1` 续传，不得因再次传入 `mode=full` 而重置。本方案不提供运行中强制重置开关，避免普通调度误删断点。每 50 个日期更新一次 progress，`lastSuccessKey` 只能推进到“从起点连续成功”的最后日期，失败日之后的成功不得越过缺口更新断点。单日首次失败立即原地重试 1 次；仍失败则入 retry queue，progress 保持 `RUNNING`。
3. 同步记录必须写入 `mode=full`、`rangeStart=19901219`、`rangeEnd`、`dateCount`、`rowCount`、`failedDates`；只有 retry queue 中该任务/范围不存在 `status != SUCCEEDED` 的项、`failedDates=[]` 且覆盖校验通过时，才将 progress 写为 `COMPLETED` 并写 `SUCCESS`。否则写 `FAILED`，progress 继续为 `RUNNING`。
4. 首次全量成功后，增量模式从已验证的最新日期加 1 日开始；不允许再使用“两年前”作为下界。
5. `000300.SH` 的历史起点常量固定为 `20050104`。Readiness 要求：存在 `rangeStart=19901219` 且无失败日的成功 full base log；从该 log 的 `rangeEnd+1` 到 `dataAsOf` 存在无断点的成功增量链；retry queue 在该任务/范围不存在 `status != SUCCEEDED` 的项；最终表中从 `20050104` 到 `dataAsOf` 的每个 SSE 开市日都有且仅有一条 `000300.SH` 记录。任一条件不满足都是 NOT_READY，不通过推迟“首个报价日”或减少基准样本规避。
6. `TushareClient.DOCUMENTED_RATE_LIMIT_MS` 为 `index_daily` 固定增加项目内部安全上限：120ms 最小请求间隔（最多 500 次/分钟），同一 API 串行，不并发绕过；即使数据提供方额度更高也不自动放宽。遇到 40203 时按现有默认值等待 65,000ms，最多重试 3 次；耗尽后交给第 2 条的失败日机制。8,797 个 SSE 开市日的理论最小扫描时间约 17.6 分钟，运行报告记录实际请求数、40203 次数、重试和总时长。

抽查数值只用于可行性证明，不写入永久单测断言；市场数据后续同步或修正会改变结果。

### 3.3 可复用模块与边界

正确的复用方式是抽取小型领域服务和统一定义，不是让统计接口调用某个现有聚合接口后再次聚合。

### 3.4 已确认的语义冲突

1. RSI：择时模块以 RSI6 从 `<20` 回升至 `>=20` 为买入；选股模块把当日 `<20` 状态直接算作买入。
2. BOLL：跌破下轨在择时模块是 warning，在选股模块被计为买入条件。
3. `MA_BULLISH` 实际判断 `close > boll_mid && macd_dif > 0`，并非均线多头排列。
4. MACD/KDJ 穿越逻辑散落在分析、择时和选股路径，没有统一 `signalKey + parameters + semanticsVersion`。
5. `/technical` 使用本地复权后计算，`/factors/latest` 使用 Tushare 预计算，两条路径没有数据源或算法版本标识。
6. 部分代码把 `DIF == 0` 直接归入“零轴下”，边界定义不严谨。

在统一服务上线前，旧接口只能标记为 legacy，不能宣称与新统计完全同口径。

## 4. 领域定义与统计口径

### 4.1 统一术语

| 术语                   | 定义                                                                                            |
| ---------------------- | ----------------------------------------------------------------------------------------------- |
| `dataAsOf`             | 日线、复权因子、停牌表、所属交易所日历，以及启用基准时的指数日线共同达到 READY 的最后市场交易日 |
| 信号事件               | 指标从非触发状态跨入触发状态的唯一日期，不是持续状态                                            |
| `occurrenceCount`      | 信号日期落在统计窗口内的事件总数                                                                |
| `eligibleOutcomeCount` | 目标 T+N 已不晚于 dataAsOf 的事件数                                                             |
| `validOutcomeCount`    | 到期且入场价、出场价、复权因子均完整的事件数                                                    |
| `immatureCount`        | 目标 T+N 晚于 dataAsOf、尚未到期的事件数                                                        |
| `missingCount`         | 已到期但入场日或目标日存在已确认合法停牌、因而无报价的事件数                                    |
| 原始收益               | 不考虑信号方向的股票复权收益                                                                    |
| 方向性收益             | 多头等于原始收益，空头等于原始收益取反                                                          |
| 超额收益               | 个股原始收益减去同日期、同入场模式的沪深 300 收益                                               |
| `MFE`                  | 从入场到目标日路径内最大有利复权波动                                                            |
| `MAE`                  | 从入场到目标日路径内最大不利复权波动                                                            |
| `CONTEXTUAL`           | 量能状态事件；只统计原始/超额收益，不计算方向性成功率                                           |

必须满足：

`occurrenceCount = eligibleOutcomeCount + immatureCount`

`eligibleOutcomeCount = validOutcomeCount + missingCount`

raw 和 directional 收益统计的分母为 `validOutcomeCount`；excess 的分母为 `validOutcomeCount - benchmarkMissingCount`；MFE/MAE 的分母为 `completePathCount`。三类分母均在响应中显式返回，绝不把 null 当 0。

每个 horizon 还必须满足 `upCount + downCount + flatCount = validOutcomeCount` 和 `completePathCount + partialPathCount = validOutcomeCount`。任一计数恒等式在运行时不成立时，不返回部分结果，而是记录结构化错误并返回 500 `TECHNICAL_SIGNAL_INTERNAL_ERROR`。

指标算法参数固定如下：

| 指标    | `technical-indicator.v2` 算法                                                           | 首个可评估点     |
| ------- | --------------------------------------------------------------------------------------- | ---------------- |
| MACD    | QFQ close；EMA12/EMA26，`k=2/(n+1)`，首个 close 初始化；DEA=EMA9(DIF)，柱=`2×(DIF-DEA)` | 第 35 条有效行情 |
| KDJ     | QFQ high/low/close；9 日 RSV；K/D 初始 50；`K=2/3×prevK+1/3×RSV`，D 同理，`J=3K-2D`     | 第 9 条有效行情  |
| RSI6    | QFQ close 差值；前 6 个涨跌幅算术均值初始化，此后 Wilder `(prev×5+current)/6`           | 第 7 条有效行情  |
| BOLL    | QFQ close 的 20 日简单均值；总体方差除以 20；上下轨为 mid±2σ                            | 第 20 条有效行情 |
| MA      | QFQ close 的简单移动平均 MA5/10/20/60                                                   | 第 60 条有效行情 |
| SAR     | QFQ high/low/close；初始 AF=0.02、步长=0.02、上限=0.20；按下文固定状态机递推            | 第 2 条有效行情  |
| 量比 20 | 当前原始 vol ÷ 当前日前 20 条有效行情 vol 均值，不包含当前日                            | 第 21 条有效行情 |

“有效行情”指同时存在合法 OHLC、vol 和正数 AdjFactor 的个股行情记录。OHLC 必须均为有限正数，且 `high >= max(open, close, low)`、`low <= min(open, close, high)`；vol 必须为有限且 `>=0`；AdjFactor 必须为有限且 `>0`。任一不满足就是数据集级 409，不得从时间线删掉该行继续计算。停牌日没有行情，不推进指标序号；无法由 `SuspendD` 解释的开市日缺口属于数据未就绪，不得当作停牌跳过。

指标递推公式不留实现自由度：

- MACD：`EMA_n(1)=close(1)`，`EMA_n(t)=EMA_n(t-1)+(2/(n+1))×(close(t)-EMA_n(t-1))`；`DIF=EMA12-EMA26`，`DEA(1)=DIF(1)`，此后按 EMA9 同式递推。前 34 条虽参与递推，对外仍标记 `NOT_EVALUABLE`。
- KDJ：`LL9=min(low[t-8..t])`、`HH9=max(high[t-8..t])`，`RSV=100×(close-LL9)/(HH9-LL9)`；`HH9=LL9` 时 RSV 固定为 50。第一个 9 日窗口前的 `prevK/prevD` 均为 50，此后按表中公式递推。
- RSI6：`gain=max(closeDiff,0)`、`loss=max(-closeDiff,0)`；前 6 个 closeDiff 的 gain/loss 算术均值初始化 `avgGain/avgLoss`，此后各用 `(prevAvg×5+current)/6`递推。`avgLoss=0 && avgGain>0` 时 RSI=100，两者均为 0 时 RSI=50，否则 `RSI=100-100/(1+avgGain/avgLoss)`。
- BOLL：`mid=sum(close[t-19..t])/20`，`σ=sqrt(sum((close-mid)^2)/20)`，`upper=mid+2σ`，`lower=mid-2σ`。
- MA：`MA_n=sum(close[t-n+1..t])/n`，不使用 EMA，不用部分窗口出值。
- SAR：初始趋势为 `close(2)>close(1)` 时多头，否则空头；初始 EP 取第 1 条 high/low，初始 SAR 取第 1 条 low/high。每日先算 `candidate=SAR+AF×(EP-SAR)`；多头 candidate 取其与前 1/前 2 条 low 的最小值，空头取其与前 1/前 2 条 high 的最大值。多头仅在 `current.low < candidate` 时翻空，空头仅在 `current.high > candidate` 时翻多；翻转日 SAR=翻转前 EP，EP=当日 low/high，AF 重置 0.02。未翻转时，只有创新 high/low 才更新 EP 并令 `AF=min(AF+0.02,0.20)`；相等不翻转、不提高 AF。
- 量比 20：`ratio=vol(t)/(sum(vol[t-20..t-1])/20)`；当日 vol 允许为 0，但前 20 条的均量必须大于 0，否则当日量比为 `NOT_EVALUABLE`。

表中“首个可评估点”是首个可输出完整指标的行情。事件 evaluator 必须同时拥有 previous 和 current 两个可评估点，因此每个信号族的最早事件日是其首个可评估点之后的第 1 条有效行情。

规则约束：

- 任何必需字段为 null 时当日结果为 `NOT_EVALUABLE`，不产生事件；
- 相等只属于穿越前一侧，穿越日必须严格大于/小于，避免边界重复；
- 指标引擎从股票首个有效日线递推到 `dataAsOf`；仅统计信号日位于请求窗口内的事件；
- 不允许同一 `signalKey + semanticsVersion + tsCode + signalDate` 重复；
- `source = LOCAL_QFQ_OHLCV`、`indicatorAlgorithmVersion = technical-indicator.v2` 固定写入元数据；标准结果不混入 `StkFactor` 计算值；
- 前复权价格固定为 `rawPrice(d) × AF(d) / AF(dataAsOf)`，OHLC 使用同一公式，成交量不复权；
- 指标判定使用未舍入 double；证据 DTO 才按字段精度格式化，舍入值不得回流到 evaluator；
- `volume-ratio20` 的分母固定为当前日之前 20 条有效个股行情的成交量均值，不包含当前日；不足 20 条时为 `NOT_EVALUABLE`；
- RSI v1 的 30/70 与旧路径的 20/80、回升触发不同；旧接口固定标记为 `legacy.v1`，标准接口不返回旧语义事件。

### 4.3 时间窗口

- 所有日期以 `Asia/Shanghai` 解释并序列化为 `YYYYMMDD`，数据库继续使用 `DATE`；
- 未传 `asOfTradeDate` 时，解析为该请求实际依赖数据集的最后共同 READY 交易日；
- 显式传入日期时，该日必须是开市日且数据 READY，不允许悄悄回退；
- `1Y`：从 `dataAsOf` 向前减一个公历年，取不早于该日期的第一个开市日；
- `3Y`：同理向前减三个公历年；
- 自定义窗口必须 `startDate <= endDate <= dataAsOf`，跨度不超过 10 年；
- 闰年使用日历运算，不用固定 365/1095 天替代。
- 为了给未到期样本返回确定的 `targetTradeDate`，所属日历在 `dataAsOf` 之后必须至少还有 `max(horizons)` 个开市日；不足时返回 409 `TECHNICAL_SIGNAL_DATA_NOT_READY`，不用自然日估算目标日。

### 4.4 T+N 与停牌

`T+N` 是信号日 T 之后所属证券交易所的第 N 个 `is_open='1'` 日期。项目的 `TradeCal` 事实源只有 SSE/SZSE，因此路由固定为 `.SH → SSE`、`.SZ → SZSE`、`.BJ → SSE`。北交所证券使用同日的 A 股开市日序列，代码不得查询库中不存在的 `BSE` 枚举，也不得运行时猜测或回退。对应 SSE/SZSE 日历不存在或未 READY 时，接口返回 `TECHNICAL_SIGNAL_DATA_NOT_READY`。

入场日或目标市场日存在、但该股票在 `SuspendD` 有对应停牌事实而没有日线时：

- 不把股票恢复交易后的第一条行情当作 T+N；
- `qualityStatus = MISSING`；入场日使用 `ENTRY_QUOTE_MISSING`，目标日使用 `TARGET_QUOTE_MISSING`；
- 进入 `missingCount`，不进入收益分母；
- 明细保留预期目标日和缺失原因。

### 4.5 复权收益

接口支持两种入场口径：

```text
SIGNAL_CLOSE（默认）
R(T, h) = [close(T+h) × AF(T+h)] / [close(T) × AF(T)] - 1

NEXT_OPEN
R(T, h) = [close(T+h) × AF(T+h)] / [open(T+1) × AF(T+1)] - 1
```

其中 `AF` 为 `AdjFactor.adjFactor`。前复权价格还包含共同锚点因子，但在收益率比值中抵消，因此上述比值与同一锚点的前复权收益一致。

约束：

- `NEXT_OPEN` 的 h=1 表示 T+1 开盘入场、T+1 收盘退出；
- 入场日或目标日因已确认停牌而无报价时，该 horizon 记为样本级 MISSING；无 `SuspendD` 事实的缺口返回接口级 409；
- 任一已存在报价的 OHLC 非有限数或 `<=0`，或对应复权因子缺失、重复、非有限数、`<=0`，均视为数据集不完整并返回接口级 409，不降级成单个缺失样本；
- 不使用 `StkFactor.pctChg`；不使用未经复权的 `Daily.close` 比值；
- 内部使用未舍入 double 计算，API 输出百分比统一保留 6 位小数；
- 平盘判定使用收益率绝对值 `<= 1e-8`，展示舍入不能改变分类；
- 基准固定默认 `000300.SH`，使用相同信号日、目标市场日和入场模式；指数点位不做复权，`excessReturn = stockReturn - benchmarkReturn`；
- `SIGNAL_CLOSE` 基准从信号日沪深 300 收盘到目标日收盘；`NEXT_OPEN` 基准从 T+1 开盘到目标日收盘；
- 信号入场日或目标日早于 `000300.SH` 历史起点 `20050104` 时，个股 raw/directional outcome 仍可为 VALID，excess 为 null，缺失原因固定为 `BENCHMARK_NOT_LISTED` 并计入 `benchmarkMissingCount`。
- `20050104` 及之后的任一 SSE 开市日缺失 `000300.SH` 行情，都是数据集级不完整：ReadinessService 产生告警并返回 409 `TECHNICAL_SIGNAL_BENCHMARK_NOT_READY`，不返回部分超额统计，也不把该缺口计为普通样本缺失。

### 4.6 统计量

对每个 `period × signalKey × horizon` 独立统计：

```text
upCount       = count(rawReturn >  epsilon)
downCount     = count(rawReturn < -epsilon)
flatCount     = count(abs(rawReturn) <= epsilon)
upRatio       = upCount / validOutcomeCount
downRatio     = downCount / validOutcomeCount
flatRatio     = flatCount / validOutcomeCount

directionalReturn = direction == BULLISH ? rawReturn
                  : direction == BEARISH ? -rawReturn
                  : null
successCount      = count(directionalReturn > epsilon)
failureCount      = count(directionalReturn < -epsilon)
directionalFlatCount = count(abs(directionalReturn) <= epsilon)
successRatio      = successCount / validOutcomeCount
```

对 BULLISH/BEARISH 必须满足 `successCount + failureCount + directionalFlatCount = validOutcomeCount`；响应中 `DirectionalDistributionDto.flatCount` 就是 `directionalFlatCount`。CONTEXTUAL 不计算上述计数，其 directional DTO 的 `sampleCount/successCount/failureCount/flatCount` 固定为 0，比例和分布字段固定为 null。

同时返回：`average`、`median`、`minimum`、`maximum`、样本标准差 `stdDev`、线性插值的 `p25/p75`。分位数对升序数组使用 zero-based rank `r=(n-1)×p`，`lo=floor(r)`、`hi=ceil(r)`，结果为 `x[lo]+(r-lo)×(x[hi]-x[lo])`；median 就是 `p=0.5`，p25/p75 分别为 0.25/0.75。有效样本为 0 时，这些值全部为 null，比例不返回 0。`CONTEXTUAL` 事件的 directional 计数固定为 0、比例/分布固定为 null，不伪造多空成功率。

样本标准差采用 `n - 1`：

```text
s = sqrt(sum((x_i - mean)^2) / (n - 1))
```

`n = 1` 时 `stdDev = null`。排序与分位数只在单个分组的有效收益数组中完成；单股样本量由 10 年请求窗口限制，不存在无界内存增长。

窗口重叠的多个信号仍分别计为独立事件，同时按第 6.2 节的区间规则返回 `overlappingOccurrenceCount` 和 `OVERLAPPING_OUTCOMES`。统计是条件分布描述，不宣称样本相互独立。

### 4.7 MFE/MAE 与置信区间

- 路径按所属交易所开市日逐日检查到目标日收盘；`SIGNAL_CLOSE` 从 T+1 开始到 T+N，不纳入信号日收盘入场之前已发生的 high/low；`NEXT_OPEN` 从 T+1 开盘入场，因此纳入 T+1 至 T+N 的 high/low；
- `SIGNAL_CLOSE` 的入场价为信号日复权收盘，`NEXT_OPEN` 的入场价为 T+1 复权开盘；
- raw MFE 初始值为 0，再取路径内各复权 high 相对入场价收益的最大值；raw MAE 初始值为 0，再取路径内各复权 low 相对入场价收益的最小值。因此 raw MFE 必须 `>=0`，raw MAE 必须 `<=0`；
- BULLISH 的 directional MFE/MAE 等于 raw MFE/MAE；BEARISH 的 directional MFE 等于 `-rawMAE`，directional MAE 等于 `-rawMFE`；CONTEXTUAL 的 directional MFE/MAE 为 null；
- 中间某个市场日因 `SuspendD` 已确认停牌而缺个股行情时，目标日收益仍可为 VALID，但 `pathCoverageStatus=PARTIAL`，MFE/MAE 为 null，并返回 `pathMissingDates`；中间缺口无停牌事实时整个请求返回 409；
- 均值 95% 区间对全部 `n>=2` 使用 `df=n-1` 的 Student-t 0.975 分位数，公式为 `mean ± t(0.975,df)×s/sqrt(n)`；`n=1` 返回 null，不在 `n>=30` 时偷换为 1.96。`t` 分位数由纯函数数值求解：Student-t CDF 使用正则化不完 Beta，Beta 连分数使用 Lentz 算法，分位数在 `[0,100]` 二分，绝对误差 `<=1e-12`、最多 200 次；未收敛视为内部错误并返回 500，不返回近似值；
- 成功率 95% 区间使用 Wilson score，`z=1.959963984540054`、`p=successCount/n`、`den=1+z²/n`、`center=(p+z²/(2n))/den`、`half=z×sqrt(p(1-p)/n+z²/(4n²))/den`，下/上界为 `max(0,center-half)` / `min(1,center+half)`；`n=0` 返回 null；
- 固定回显 `confidenceLevel=0.95` 和 `confidenceIntervalVersion=student-t-wilson.v1`。

依赖方向：

```text
Controller → StatisticsService → OccurrenceService / OutcomeService / Calculator
                              ↓
                     TechnicalSignalDataPort
                              ↓
                  PrismaTechnicalSignalRepository

Stock / ScreenerSubscription ──→ TechnicalSignalDefinitionService / OccurrenceService（只依赖导出能力）

Tushare MarketSyncService ──→ Daily / AdjFactor / TradeCal / SuspendD / IndexDaily
                                                      ↓
                                      TechnicalSignalDataPort（只读）
```

模块原则：

- `TechnicalSignalModule` 注册到 `src/app.module.ts`；路由仍使用 `/stock/detail/analysis/...` 保持产品信息架构一致；
- 只依赖全局 `PrismaService`、`CacheService` 和 Logger，不导入 `StockModule` 或 `TushareModule`，避免循环依赖；
- `MarketSyncService` 只负责修复并维护 `IndexDaily` 事实数据；统计模块不调用 Tushare API，也不在用户请求内触发同步，只通过 Readiness 拒绝不完整数据；
- Repository 只负责批量加载与数据形状转换，不包含业务统计；
- Registry 只保存不可变信号定义，`TechnicalSignalDefinitionService` 是唯一可注入的 Catalog/evaluator 门面；Calculator 是无 IO 纯函数；编排 Service 不复制指标公式；
- 导出 `TechnicalSignalDefinitionService`、IndicatorEngine 和 Occurrence evaluator 供 `stock-screener` 和条件订阅使用，内部 Registry 不直接跨模块暴露，禁止复制判断表达式；
- 旧 `/technical`、`/timing-signals`、`/factors` 接口保持响应兼容并固定标记 `legacy.v1`；标准统计接口不读取 Legacy 事件。

### 5.3 与条件订阅设计的衔接

《条件订阅规则引擎》已计划统一技术事件、`TechnicalSignalDailySnapshot` 和 `TechnicalSignalEvent`。本方案遵循以下单一事实源约束：

1. 信号目录、语义版本和 evaluator 归 `technical-signal` 模块的 `TechnicalSignalDefinitionService` 所有；
2. 条件订阅的 SIGNAL_EVENT evaluator 依赖该模块导出的定义与事件，不另写 MACD/KDJ/MA/SAR/量比判断；
3. 本模块 occurrence 是按需计算结果，不落库；
4. 条件订阅写入自己的 `TechnicalSignalDailySnapshot` / `TechnicalSignalEvent`，唯一键和执行历史由订阅设计负责；
5. 订阅批处理 detector 与本模块纯 TypeScript detector 必须使用同一包导出，并以 parity test 保证同一输入逐事件差异为 0；
6. 统计查询不切读订阅事件表，避免任务失败、回填延迟或订阅保留策略改变单股统计结果。

订阅 `metricId + eventType` 与本 Catalog 的映射固定如下，不由前端或订阅执行器拼字符串：

## 7. 数据访问与计算流程

### 7.1 数据快照与 READY 判定

`TechnicalSignalReadinessService` 返回：

```ts
export interface TechnicalSignalDataSnapshot {
  ready: boolean
  dataAsOf: string
  dataVersions: {
    tradeCal: string
    daily: string
    adjFactor: string
    indexDaily: string | null
    suspendD: string
  }
  missing: string[]
  coverage: {
    expectedOpenDays: number
    requiredFutureOpenDays: number
    availableFutureOpenDays: number
    legitimateSuspensionDays: number
    dailyRows: number
    adjFactorRows: number
    unexplainedStockGapDays: number
    benchmarkExpectedOpenDays: number
    benchmarkRows: number
    benchmarkGapDays: number
    suspendRows: number
  }
}
```

判定顺序：

1. 从 `TushareSyncLog` 成功任务与目标表水位取得 `TRADE_CAL/DAILY/ADJ_FACTOR/SUSPEND_D` 的版本；`includeBenchmark=true` 时同时要求 `INDEX_DAILY`。
2. `includeBenchmark=true` 时，必须先通过第 3.2 节的 `INDEX_DAILY` full base log、其后增量链和 `000300.SH` 日期完整性门禁；只有近两年数据、无 full base、增量断链、日志为 FAILED、retry queue 未清空或任一 SSE 开市日缺失时，均返回 409 `TECHNICAL_SIGNAL_BENCHMARK_NOT_READY`。
3. 最新查询取请求实际依赖数据集共同完成的最后开市日，不直接使用系统日期。
4. 显式历史 as-of 必须不晚于请求所需数据集的共同水位，并存在第 4.4 节固定路由的交易日历；该日历在 as-of 后的开市日数还必须达到 `maxHorizon`，具体覆盖数回显到 `requiredFutureOpenDays/availableFutureOpenDays`。`includeBenchmark=false` 时 `IndexDaily` 不参与 `dataAsOf`。
5. 对请求股票从上市日至 `dataAsOf` 检查日线与复权因子覆盖：`Daily` 缺口在同日 `SuspendD` 有合法停牌记录时计入 `legitimateSuspensionDays`；否则计入 `unexplainedStockGapDays` 并返回 409。任一有效日线对应的 `AdjFactor` 缺失、重复或非正数也返回 409。
6. 不能因为股票停牌而把市场 `dataAsOf` 回退到该股最后交易日。全局同步或全历史输入不完整是接口级 409；只有统计窗口内单个已到期目标日因已确认停牌而缺行情，才是样本级 MISSING。
7. `dataVersions` 使用成功同步日志 ID/完成时间和表水位的稳定组合，参与缓存 key；`INDEX_DAILY` 版本还必须包含 full base log ID/起止日期、最新 incremental log ID/水位和 `000300.SH` 覆盖行数。

现有 `SubscriptionDataReadinessService` 可作为覆盖率和 sync log 校验参考，但应把通用数据集水位能力抽到共享服务，避免技术统计依赖订阅模块。

### 7.2 批量加载

一次请求执行固定数量批量查询，不按信号或 occurrence 查询数据库：

1. 股票基本信息与交易所：1 次；
2. 从上市日至 `dataAsOf` 的日线：1 次；
3. 从上市日至 `dataAsOf` 的复权因子：1 次，与日线并行；
4. 覆盖窗口、最大 horizon 和路径日期的所属交易所日历：1 次；
5. 同范围停牌记录：1 次，与日线/复权因子并行；
6. 开启基准时加载同范围沪深 300 日线：1 次；
7. 同步日志与实际表水位由 ReadinessService 合并批量读取，不得按数据集循环查询。

Prisma 查询必须 `select` 必需字段，按 `(tsCode, tradeDate)` 范围读取。现有主键/索引满足单股全历史查询，不新增索引：

```ts
await prisma.daily.findMany({
  where: {
    tsCode,
    tradeDate: { gte: listDate, lte: dataAsOf },
  },
  orderBy: { tradeDate: 'asc' },
  select: {
    tradeDate: true,
    open: true,
    high: true,
    low: true,
    close: true,
    preClose: true,
    vol: true,
    amount: true,
  },
})
```

如果改用 `$queryRaw` 聚合 JOIN，只允许 `Prisma.sql` 参数化值和固定白名单表名；严禁拼接 tsCode、日期、signalKey。查询计划必须命中现有复合索引。

### 7.3 事件检测

伪代码：

```ts
const indicatorPoints = indicatorEngine.computeFullHistory(qfqBars)

for (let i = 1; i < indicatorPoints.length; i += 1) {
  const previous = indicatorPoints[i - 1]
  const current = indicatorPoints[i]
  if (current.tradeDate < windowStart || current.tradeDate > windowEnd) continue

  for (const definition of selectedDefinitions) {
    const evidence = definition.evaluate(previous, current)
    if (!evidence) continue
    occurrences.push(toOccurrence(definition, current.tradeDate, evidence))
  }
}
```

相邻点是相邻的个股有效行情记录，不要求自然日连续。所属交易所开市但个股无行情时，ReadinessService 必须借助停牌数据区分合法停牌与同步缺口：合法停牌不打断指标递推；无法解释的缺口或任一有效行情缺 AdjFactor 时返回 `TECHNICAL_SIGNAL_DATA_NOT_READY`，禁止带 warning 继续计算。窗口第一日事件由全历史递推后的前一有效行情状态决定。

### 7.4 目标日与收益

Repository 把开市日按升序建立 `tradeDate → ordinal` 映射。对信号日在 ordinal `i` 的 occurrence，目标日为 `calendar[i + horizon]`，时间复杂度 O(1)。

```ts
for (const occurrence of occurrences) {
  for (const horizon of horizons) {
    const targetDate = openDates[ordinalByDate.get(occurrence.signalDate)! + horizon]

    if (!targetDate) {
      throw new TechnicalSignalDataNotReadyError('TRADE_CAL_FUTURE_COVERAGE_MISSING')
    }

    if (targetDate > dataAsOf) {
      addImmature(occurrence, horizon, targetDate)
      continue
    }

    const entryDate =
      entryMode === 'SIGNAL_CLOSE' ? occurrence.signalDate : openDates[ordinalByDate.get(occurrence.signalDate)! + 1]

    const outcome = calculateAdjustedReturn(
      quoteByDate.get(entryDate),
      adjustmentByDate.get(entryDate),
      quoteByDate.get(targetDate),
      adjustmentByDate.get(targetDate),
      entryMode,
    )
    addOutcome(occurrence, horizon, outcome)
  }
}
```

复杂度为 O(Q×S + E×H×P)，其中 Q 是单股全历史行情数、S 固定为最多 14 个定义、E 是窗口内事件数、H 是 horizon 数、P 是单个 horizon 的路径长度；MFE/MAE 通过日期 ordinal 和预构建价格 Map 计算，不产生数据库 N+1。

### 7.5 聚合顺序

必须按以下顺序执行：

1. 解析稳定信号版本；
2. 解析 dataAsOf 与 period 边界；
3. 一次加载最大时间范围；
4. 对最大范围检测 occurrence；
5. 对每个 period 过滤事件；
6. 为事件计算所有 horizon outcome；
7. 按 `period × signalKey × horizon` 对完整样本聚合；
8. 生成摘要；明细接口最后才分页。

禁止“先分页事件、再对当前页求平均”的实现。

### 7.6 Redis 缓存

新增 `src/constant/cache.constant.ts` namespace：`STOCK_TECHNICAL_SIGNAL_STATISTICS`。

```text
key = sha256(
  canonicalRequest
  + dataAsOf
  + sorted(dataVersions)
  + sorted(definitionHashes)
  + indicatorAlgorithmVersion
  + statisticsAlgorithmVersion
  + returnPolicyVersion
  + confidenceIntervalVersion
  + benchmarkTsCode
)
TTL = 24h
```

- canonicalRequest 对 signals 按 `signalKey+semanticsVersion`、periods、horizons 排序后序列化；输入重复值在 DTO 层返回 400，不在缓存层静默去重；
- 数据修正或新同步会产生新 dataVersion，自然旁路旧 key，无需危险的全库 key scan；
- Redis 不可用时 fail-open，直接计算并记录 `cache_unavailable`，不能让核心查询失败；
- 不缓存 4xx/5xx、未 READY 或含内部异常的结果；合法的 200 响应即使 `occurrenceCount=0` 也正常缓存；
- 防击穿锁 TTL 固定 5 秒；未拿到锁的请求每 100ms 重查缓存、最多等待 1 秒，仍未命中后独立计算；
- 缓存 payload 保留首次计算完成时的 `computedAt`；每次响应在缓存外注入当前 `servedAt` 和 `cacheHit`。不把用户标识写入共享缓存内容。

## 8. 存储与一致性决策

本方案不修改 Prisma Schema，也不持久化派生指标、事件、outcome 或聚合结果。固定理由如下：

1. 单股全历史读取硬上限为 12,000 条有效行情；当前 A 股历史长度在该上限内，全历史指标递推和 10 年窗口聚合受固定资源边界约束；
2. 原始日线、复权因子、交易日历、基准指数和算法版本足以确定性重建全部结果；
3. 持久化派生结果会引入行情修正、复权因子修正、算法升级和 Catalog 升版的多维回填一致性成本；
4. Redis key 包含全部数据版本和算法版本，只承担性能缓存，不承担事实存储；
5. Redis 丢失、逐出或不可用时，接口从原始事实源重算，结果语义不变。

《条件订阅规则引擎》中的 `TechnicalSignalDailySnapshot` / `TechnicalSignalEvent` 仅服务全市场订阅执行。两边共享同一个 evaluator 包，但本统计接口不读取订阅表。由此避免订阅批次延迟、失败、保留期或回填状态改变单股统计结果。

## 9. 安全、可观测性与运维

### 9.1 安全与资源边界

- 沿用全局 JWT Guard；不得新增公开匿名路由；
- tsCode、日期、signalKey、horizon 全部白名单/格式校验，Repository 不接受自由 SQL 片段；
- 单请求最多 14 个定义、10 个 horizon、10 年窗口、12,000 条全历史行情、明细 100 条/页；
- evidence 只返回定义声明的指标字段，不序列化完整数据库行；
- 日志不记录 access token、完整请求头或数据库连接信息；
- 数据库 statement timeout 固定 2500ms、应用总超时固定 3000ms，任一超时返回结构化 503；
- 对昂贵冷查询使用功能级限流和缓存防击穿；
- 统计结果仅为历史描述，API/Swagger 明确非投资建议。

### 10.1 测试原则

- CUSTOM 字段组合校验；
- 未登录、无权限、限流；
- 股票不存在、数据未 READY、无日线/复权覆盖、基准未 READY；
- `includeBenchmark=true` 时缺 full log、仅两年基准、`20050104..dataAsOf` 中间 gap 均返回 409；`includeBenchmark=false` 不受 IndexDaily 水位影响；
- 明细稳定分页，page 变化不影响 total；
- ratio 为 0～1、ReturnPct 不重复乘 100、null 不转 0；
- CONTEXTUAL 不返回方向性成功率，BULLISH/BEARISH 的方向性结果正确；
- benchmark、MFE/MAE、Student-t/Wilson 字段与固定 fixture 一致；
- 错误中不出现 SQL、绝对路径、堆栈或 token；
- 生成的 OpenAPI 中 request/response schema 非空且字段单位明确。

### 10.5 PostgreSQL 集成与独立 SQL 对账

测试数据库 seed `StockBasic/Daily/AdjFactor/TradeCal/IndexDaily/SuspendD/TushareSyncLog`，每例使用事务回滚或独立 schema 清理。集成测试覆盖上市日至 as-of 的日线/复权关联、除权、合法停牌、无法解释的行情 gap、`.SH/.SZ/.BJ` 固定日历路由、基准 full log、基准起点后 gap 和 sync watermark 不一致。

三套 oracle 的职责固定为：

1. 手算纯函数 fixture：验证指标递推、14 个事件、收益、MFE/MAE 和置信区间；
2. 独立 SQL：只验证事实数据抽取、前复权 OHLC、T+N 日期、基准日期和目标收益，不在 SQL 中复制 TypeScript 指标算法；
3. API：验证完整编排、DTO、缓存和响应单位。

独立 SQL 的前复权价格必须使用参数化 `asOfAdjFactor`：

```sql
SELECT
  d.trade_date,
  d.open * af.adj_factor / $3 AS qfq_open,
  d.high * af.adj_factor / $3 AS qfq_high,
  d.low * af.adj_factor / $3 AS qfq_low,
  d.close * af.adj_factor / $3 AS qfq_close,
  d.vol
FROM stock_daily_prices d
JOIN stock_adjustment_factors af
  ON af.ts_code = d.ts_code AND af.trade_date = d.trade_date
WHERE d.ts_code = $1
  AND d.trade_date BETWEEN $2 AND $4
ORDER BY d.trade_date;
```

对 Golden Fixture 必须达到“手算事实/算法 oracle = SQL 数据 oracle + 纯函数 detector = API”一致。查询执行 `EXPLAIN (ANALYZE, BUFFERS)`，单股全历史范围查询必须命中 `(ts_code, trade_date)` 主键/索引，不允许全表扫描或按 occurrence/path N+1。

### 10.6 真实数据抽样对账

从真实库确定性抽样至少 30 只股票，覆盖沪/深/北、主板、创业板、科创板、新股、长期停牌和复权因子变化标的。抽样方式和名单写入执行报告，不随测试重跑随机漂移。

每只股票至少验证：

- 1Y/3Y 的全部 14 个标准事件日期；
- T+1/T+5 的预期市场日、有效/缺失/未到期分类；
- 复权收益和涨跌分类；
- 沪深 300 基准收益、超额收益、MFE/MAE 和路径覆盖；
- 汇总计数恒等式及均值/极值；
- API 的 dataAsOf/dataVersions/definitionHash/indicatorAlgorithmVersion。

逐事件日期和计数差异必须为 0；浮点绝对误差 `<1e-8`。`000001.SZ` 的既有只读测算可作 smoke baseline，但不能把会随数据修正变化的市场数值写成永久单测。

### 10.7 性能、负载、压力与耐久

基准请求：单股全历史指标递推、3 年统计窗口、14 类信号、5 个 horizon、沪深 300 基准和 MFE/MAE；明细场景另取 100 条。

| 场景         | 验收目标                                                                                 |
| ------------ | ---------------------------------------------------------------------------------------- |
| 单请求冷缓存 | 摘要 p95 < 750ms，p99 < 1.5s                                                             |
| 单请求热缓存 | 摘要 p95 < 100ms                                                                         |
| LOAD         | 20 VU、10 分钟、至少 100 个标的；p95 < 750ms、p99 < 1.5s、错误率 < 0.1%、吞吐 ≥ 20 req/s |
| STRESS       | 20→50→100 VU；5xx > 5%、CPU 连续 2 分钟 > 85% 或连接池 > 90% 即停止                      |
| SOAK         | 10 VU、60 分钟；末段 p95 相比首段恶化 < 20%，RSS 增长 < 10%，连接数回归基线              |

过载时只允许结构化 429/503，不得进程崩溃；停止压力后 60 秒内恢复。仓库未安装专用压测器时，沿用 Jest + `node:perf_hooks` 编写 `test/fresh/technical-signal-statistics-pressure-v1.spec.ts`，输出 JSON/Markdown 报告，不增加未经评审的生产依赖。

吞吐压测不绕过生产限流：LOAD 使用 50 个隔离测试用户轮询 token，每用户不超过 24 次/分钟；STRESS/SOAK 按相同上限增加测试用户数，保证测到的是计算/数据库容量而非单用户 429。限流本身另用单用户在 60 秒滑动窗口连续发送 31 次请求，断言前 30 次放行、第 31 次返回 429，窗口到期后恢复。
