## 2. 测试目标与完成定义

Agent 的正确性按整条业务链判定，而不是按单个节点“被调用”判定：

```text
用户问题
→ 意图、实体、范围、时点被正确理解
→ 计划只包含必要且获权的 Tool
→ Tool 输入没有缩小、放大或串错研究母体
→ Tool 结果的空值、缺失、陈旧、部分成功语义被保留
→ 每个事实结论能追溯到成功 Tool/受控来源
→ 最终回答的完成程度与事实账本一致
→ Run、事件、消息、引用和审计形成唯一一致终态
```

一个场景只有同时满足下列条件才算通过：

1. 返回值或终态符合用户任务；
2. 实际 Tool 图、输入范围和禁止调用符合 Oracle；
3. 数据日期、单位、复权、证券类型、用户归属、截断语义正确；
4. 最终结论只使用成功且可验证的事实；
5. 失败、取消、重试、恢复没有产生伪成功或重复副作用；
6. API、数据库状态、事件流和审计记录相互一致。

## 4. 用户任务地图

| 场景族           | 代表问题                                  | 必须得到的业务结果                         | 典型禁止行为                                |
| ---------------- | ----------------------------------------- | ------------------------------------------ | ------------------------------------------- |
| 单证券查询       | “茅台最新 RSI/财报/资金流”                | 唯一实体、正确 Tool、独立水位与单位        | 调全市场筛选；把 null 当 0                  |
| 多证券比较       | “比较茅台和五粮液盈利质量”                | 所有标的同口径、点时对齐、缺一不做完整排名 | 丢掉失败标的后仍声称完整比较                |
| 全市场/板块筛选  | “科创板和创业板买入信号前 10”             | 完整目标母体、每个板块精确筛选、稳定排序   | 用代表股抽样；用可用性检查替代筛选          |
| 数据可用性       | “技术因子更新到哪天”                      | 只报告覆盖与质量状态                       | 由覆盖推断股票信号或收益                    |
| 市场/行业/多资产 | “今天市场为何跌”“行业轮动”“ETF/指数/期权” | 标的类型正确、各 section 独立水位          | 股票 Tool 代查指数/基金；伪造 Greeks        |
| 事件与外部研究   | “回购后通常涨多少”“核对最新公告”          | 事件定义固定；外部事实抓取验证并带时间线   | 搜索 snippet 直接当关键事实；网页指令改计划 |
| 因子与确定性计算 | “PE 因子 IC”“估值分位”                    | 程序计算、算法版本、样本数和缺失处理明确   | 模型心算；样本不足仍给精确结论              |
| 私有研究         | “我的组合风险”“复盘这个回测”              | owner scope、点时数据、偏差告警            | ADMIN 默认跨用户；缓存命中他人结果          |
| 报告与记忆       | “保存报告”“记住我偏好简洁”                | 显式确认、幂等写入、可纠错/删除            | 对话一句话直接写；确认 token 跨内容复用     |
| 主动研究         | 每日研究、条件预警、通知                  | 交易日/水位 gate、唯一执行、投递幂等       | 旧数据冒充今日；通知失败重跑研究            |
| 恢复与控制       | 取消、刷新、断线、重试、重新生成          | 唯一终态、事件可重放、旧版本保留           | 迟到结果覆盖取消；重试重复计费/写入         |

## 5. 核心业务规则与独立 Oracle

| 规则编号 | 规则                                                                              | 来源                 | 测试判定                                            |
| -------- | --------------------------------------------------------------------------------- | -------------------- | --------------------------------------------------- |
| R-001    | 只执行完成用户任务所必需、且在 capability/Workflow/角色交集内的 Tool。            | Tool/Workflow 契约   | 对每个场景声明“必须 Tool、可选 Tool、禁止 Tool”。   |
| R-002    | 路由或计划模型失败不能改变实体、板块、证券类型、日期、数量和用户范围。            | Orchestrator 契约    | 比较正常路径和故障路径的规范化任务约束。            |
| R-003    | 必需 Tool 未成功，不能声称完整完成；可选 Tool 失败必须显式缩小结论。              | Tool 错误语义        | 回答完成度与成功事实集合精确匹配。                  |
| R-004    | 真实空集、依赖失败、数据未就绪、数据陈旧、结果截断是五种不同语义。                | Tool/API 契约        | 分别断言状态、warning、重试与回答措辞。             |
| R-005    | 证券类型、市场、板块、复权、频率、时间范围、topN 不得隐式改写。                   | Tool Schema/金融规则 | 审计实际 Tool 输入，不只断言调用次数。              |
| R-006    | 财务/事件/持仓历史必须按当时可得信息过滤，禁止前视和幸存者偏差。                  | 金融点时规则         | 使用公告日前后、成员进出、持仓事件边界 fixture。    |
| R-007    | `null` 不等于 0；比例的 PERCENT/DECIMAL、金额单位、复权口径必须保留。             | 内容块/Tool 契约     | 用可手算 fixture 检查值、单位、空值和 provenance。  |
| R-008    | 每个事实数字和外部结论必须绑定同 Run 的成功 Tool/验证引用。                       | 引用协议             | 构造缺引用、跨 Run 引用、失败 Tool 引用并要求拒绝。 |
| R-009    | userId 只取认证上下文；私有资源和缓存均按 owner 隔离。                            | 安全/REST 契约       | 双用户同 ID、枚举 ID、缓存冷热路径都测。            |
| R-010    | 写操作必须显式确认、绑定输入 hash、短时有效且业务幂等。                           | 报告/确认契约        | 未确认、过期、篡改、重放、并发确认组合。            |
| R-011    | Run 只有一个不可逆终态；取消后迟到结果不可提交。                                  | 状态/SSE 契约        | 控制并发时序，联合断言 DB、事件、消息。             |
| R-012    | 重试沿用逻辑调用身份，只增加 attempt，不重复计费或副作用。                        | 网关/Tool 契约       | 注入 timeout/429/worker crash，检查 ID 与账本。     |
| R-013    | SSE sequence 唯一递增；终态是最后业务事件；断线游标只在同 Run 有效。              | SSE 契约             | 乱序完成、重复连接、错误游标、事件清理快照。        |
| R-014    | MANUAL 模型不静默降级；AUTO 仅在允许且无权威正文时降级。                          | 模型网关契约         | 失败时点 × policy × 数据等级组合。                  |
| R-015    | 数据未到目标水位时，交互回答明确最近可用日；定时任务等待/跳过，不能冒充今日。     | Workflow/调度契约    | 同一 fixture 分别走交互与 schedule。                |
| R-016    | Prompt、网页、Tool 文本和页面上下文都不能改变权限、注册 Tool 或执行任意 URL/SQL。 | 安全契约             | 多来源注入与混淆输入；检查计划和审计。              |
| R-017    | 报告、重新生成和历史消息冻结原消息/引用/版本，不被后续 Run 改写。                 | 会话/报告契约        | 新旧版本并存和 hash 稳定性断言。                    |
| R-018    | 费用、次数、并发和结果规模限制在入队及每次高成本调用前都生效。                    | 配额契约             | 并发 reservation、边界前后、重试耗额组合。          |

## 6. 组合测试模型

不做所有维度的笛卡尔积；P0 规则使用 pairwise 覆盖，并对高风险三元交互单独加例。

| 维度      | 取值                                                                                                          |
| --------- | ------------------------------------------------------------------------------------------------------------- |
| 意图      | 单股、多股比较、全市场筛选、数据可用性、市场/行业、基金/指数/衍生品、因子/事件、私有分析、报告/记忆、定时研究 |
| 实体状态  | 唯一、歧义、无匹配、类型冲突、已退市、跨市场同名、页面上下文冲突                                              |
| 数据状态  | READY、真实 EMPTY、PARTIAL、DEGRADED、STALE、FAILED、TRUNCATED、不同数据集水位不一致                          |
| 模型状态  | 成功、非法 JSON、长度截断、Tool arguments 分片损坏、timeout、429、5xx、产生草稿后断流、引用修复失败           |
| Tool 状态 | 成功、空集、typed error、timeout 后成功、重试耗尽、部分标的失败、输出 Schema 非法、取消后迟到                 |
| 权限      | 公共、未授权 capability、本人私有资源、他人资源、ADMIN 他人资源、供应商不允许私有数据                         |
| 生命周期  | 新 Run、重复 clientRequestId、同键不同 Body、重新生成、并发发送、排队取消、运行取消、Worker 恢复、SSE 重连    |
| 输出      | 完整事实、部分事实、仅澄清、明确失败、截断、引用缺失/跨 Run/过期、风险等级冲突                                |

必须覆盖的高风险三元组合：

| 组合 ID | 三元交互                                            | 预期                                                 |
| ------- | --------------------------------------------------- | ---------------------------------------------------- |
| C-001   | 全市场筛选 × 计划模型 length × 核心 Tool 已启用     | 保持完整板块范围，走等价确定性计划；不得抽样。       |
| C-002   | 多股比较 × 单标的 Tool 失败 × 模型综合成功          | 只能给部分结果，禁止完整排名和“均已比较”。           |
| C-003   | 私有组合 × AUTO fallback × 次模型不允许敏感数据     | 拒绝次模型或只传程序聚合摘要，绝不发送明细。         |
| C-004   | 运行取消 × Tool 迟到成功 × SSE 重连                 | 最终仍 CANCELLED；迟到结果只审计；重放无 completed。 |
| C-005   | 报告确认 × 内容版本变化 × 同 clientRequestId        | 拒绝确认；不得返回旧报告或重复写日志。               |
| C-006   | 今日市场 × section 水位不一致 × 搜索成功            | 分项展示日期；外部新闻不能把旧内部数据包装成今日。   |
| C-007   | Prompt Injection × 未授权 WEB_SEARCH × Planner 成功 | 计划编译拒绝联网；回答不泄露策略或伪造联网结果。     |
| C-008   | Worker crash × Tool 已成功 × retry                  | 复用 checkpoint 和 toolCallId，不重复执行/计费。     |
| C-009   | 长会话 × MANUAL 小窗口模型 × 摘要校验失败           | 返回受控失败，不静默丢历史后继续回答。               |
| C-010   | Schedule 多副本 × 数据陈旧 × Delivery retry         | 仅一个 execution；研究不运行；Delivery 不应创建。    |

## 8. 自动化分层与证据要求

| 层级        | 目的                                             | 必须断言                                     | 不能替代什么                           |
| ----------- | ------------------------------------------------ | -------------------------------------------- | -------------------------------------- |
| 纯函数/契约 | 状态机、Schema、算法、排序                       | 输入输出、边界、错误码                       | 不能证明工作流会正确选择它。           |
| 节点集成    | classify/select/plan/tool/synthesize/verify 组合 | 规范化任务、实际 Tool 输入、事实包、最终回答 | 不能证明 API/队列/数据库一致。         |
| API 集成    | DTO、Guard、Interceptor、Repository              | HTTP、响应包装、owner、DB 状态               | 不能证明 Worker 真执行。               |
| Worker 集成 | 租约、checkpoint、重试、取消                     | Tool/Model 审计、状态、事件                  | 不能证明客户端恢复体验。               |
| E2E         | API→DB→Queue→Worker→Tool→Message→SSE             | 全链业务 Oracle                              | 不用固定 mock 返回一句话冒充真实业务。 |
| 性能/压力   | 容量、拐点、降级                                 | p50/p95/p99、吞吐、错误率、资源、数据一致性  | 不对第三方供应商施压。                 |

状态化 fake 的最低要求：能表达延迟、首次失败后成功、取消后迟到、不同用户不同数据、不同数据水位、部分标的失败、重复事件和输出损坏；禁止所有调用永远返回同一固定对象。

## 9. 性能、负载、压力与稳定性设计

| 类型   | 场景                                        | 数据/并发                      | 观察指标                                       | 停止条件                                   |
| ------ | ------------------------------------------- | ------------------------------ | ---------------------------------------------- | ------------------------------------------ |
| PERF   | 单 Run 1/3/10 个只读 Tool；最大合法结构化块 | 本地 DB/Redis，冷/热缓存各一次 | 首事件、完成 p50/p95/p99、DB query、序列化内存 | 先记录基线，不虚构阈值。                   |
| LOAD   | 1/5/10/20/50 并发用户发送+SSE               | 每用户独立会话，公共/私有 7:3  | Run 吞吐、队列等待、错误率、连接数、Redis/DB   | 错误率持续 >5% 或连接池接近耗尽。          |
| STRESS | 阶梯增加 Run、Tool 并行和大结果             | 第三方全部 fake                | 拐点、限流、公平性、OOM、恢复时间              | 内存不可恢复、DB pool 打满、队列无法回落。 |
| SOAK   | 持续交互+SSE 重连+少量取消                  | 2–4 小时本地受控负载           | RSS、heap、listener、连接、队列、重复终态      | 持续增长无回落或出现数据不一致。           |

压测后必须重新检查：幂等键、Run 终态、事件 sequence、成本账本、私有缓存隔离和未完成队列。
