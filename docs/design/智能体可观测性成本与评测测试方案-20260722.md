## 3. 业务理解

### 3.1 业务场景

运维人员需从一次 Run 找到节点、模型、Tool、SSE 和队列的失败或延迟，并能对账模型 token/cost。发布前需以版本化、可复现的 fake-provider 数据集阻止事实、引用、成本或稳定性回退；普通用户不能查询他人 trace、成本或评测结果。

### 3.2 核心业务规则

| 规则编号 | 规则 | 来源 | 测试影响 |
| --- | --- | --- | --- |
| R-001 | Prometheus label 不得包含 userId、runId、traceId、原始 URL 或动态错误正文 | Batch 025 第 11/19 节 | label 白名单与高基数测试 |
| R-002 | 单次模型尝试只计一次 usage/cost；缺失 usage 必须显式标识 unknown/estimated | Batch 025 第 11/18/23 节 | 成本对账与未知值测试 |
| R-003 | trace/log 仅 metadata，禁止 Prompt、响应全文、key、持仓和网页正文 | Batch 025 第 5/19 节 | secret/正文扫描测试 |
| R-004 | 评测结果绑定数据集、workflow、prompt、模型与用例 hash；相同输入可复现 | Batch 025 第 14/15 节 | dataset/version/idempotency 测试 |
| R-005 | 质量或成本阈值回退必须使评测命令失败 | Batch 025 第 2/23 节 | threshold gate 测试 |
| R-006 | 跨用户成本、trace 和评测产物仅管理员可查且操作可审计 | Batch 025 第 10/19 节 | 角色/越权测试 |

### 3.3 状态变化与不变量

| 类型 | 说明 |
| --- | --- |
| 数据写入 | 高频指标只进 Prometheus；评测运行/结果保存版本和摘要，不保存用户正文 |
| 缓存/队列 | Worker trace 必须延续 Run trace；重试/fallback 每 attempt 独立计数 |
| 权限边界 | `/metrics` 不含私有标签；管理员接口拒绝普通用户与未认证调用 |
| 时间规则 | 时延/TTFT 使用单调毫秒差；成本聚合按完成 attempt 和版本化价格计算 |
| 数据不变量 | 完成 attempt、token、cost 和审计记录可对账；重复评测不重复扣预算 |

## 8. 性能与压力测试设计

| 项目 | 设计 |
| --- | --- |
| 环境 | 本机 Docker PostgreSQL/Redis、Node 20、fake provider；不访问付费模型 |
| 数据规模 | 100 个 fake Run；每 Run 2 model attempt、2 Tool、10 SSE 事件 |
| 预热方式 | 先执行 10 个 Run，不纳入统计 |
| 并发模型 | 1/5/10 并发，各 30 秒或完成 100 Run |
| 指标 | p50/p95/p99、吞吐、错误率、指标 series 数、进程内存 |
| 阈值或基线 | 首轮只记录实测值；label series 不超过固定字典组合 |
| 停止条件 | 错误率超过 5%、队列持续增长、DB/Redis 不健康 |
| 数据清理 | 使用独立测试数据；清理 evaluation run 与 Redis 测试前缀 |
