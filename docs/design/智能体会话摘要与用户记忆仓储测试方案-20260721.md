## 3. 业务理解

### 3.1 业务场景

- 长会话把连续旧消息压缩成可追溯摘要，保存历史版本，并原子推进会话当前摘要指针。
- 用户表达可先形成候选记忆；只有显式确认且未撤销、未过期、未删除的记忆进入后续 Run。
- 用户纠错创建新版本并保留旧记录；用户撤销或删除后立即失效。
- Repository 是租户隔离和事务一致性的最后一道持久化边界。

### 3.2 Repository 契约

`ConversationSummaryRepository`：

- 按 `userId + conversationId` 查询当前摘要和版本历史。
- 以 `expectedSummaryVersion` 创建下一版本；摘要插入、会话 `currentSummaryId` 和 `summaryVersion` 推进必须同事务完成。
- 校验区间端点、`sourceMessageIds` 全部属于当前用户和同一会话，且来源位于摘要区间内。

`UserMemoryRepository`：

- 创建候选、显式确认、查询 active、纠错、撤销和软删除。
- 所有资源与来源查询显式接收 `userId`；跨租户资源统一表现为安全 not-found。
- 纠错在同一事务中撤销旧版本并创建 `version + 1`；不原地覆盖历史值。

### 3.3 核心业务规则

| 规则编号 | 规则                                                    | 来源           | 测试影响                                   |
| -------- | ------------------------------------------------------- | -------------- | ------------------------------------------ |
| R-001    | 原始消息和历史摘要不可覆盖                              | ADR-005        | 摘要只能追加版本                           |
| R-002    | 当前摘要创建与会话指针/版本推进原子提交                 | Batch 019      | 任一步失败全部回滚                         |
| R-003    | 摘要覆盖同用户、同会话、顺序合法的消息区间              | 会话与记忆设计 | 跨会话、跨租户、倒序、区间外来源拒绝       |
| R-004    | 摘要推进使用 expected version CAS                       | 会话与记忆设计 | 旧版本与并发写冲突，不允许 last-write-wins |
| R-005    | 只有 active `CONFIRMED` 记忆可用于新 Run                | Batch 019      | 候选、撤销、过期、删除全部排除             |
| R-006    | 用户确认是候选进入长期记忆的必要条件                    | Batch 019      | 创建候选不能直接 active                    |
| R-007    | 每个 `(userId, category, key)` 同时最多一个有效确认版本 | Batch 019      | partial unique 与并发确认必须生效          |
| R-008    | 纠错撤销旧版并新增 `version + 1`                        | ADR-005        | 历史可追溯，事务失败不留半状态             |
| R-009    | 持仓明细、交易日志、凭据、健康、政治推断禁止记忆        | 冻结策略       | 创建、确认、纠错均受策略检查               |
| R-010    | `FINANCIAL` 仅允许明确确认的 `PREFERENCE/CONSTRAINT`    | 冻结策略       | 非法类别或候选激活拒绝                     |
| R-011    | TTL 使用类别默认值且不得超过最大值                      | 冻结策略       | 过期边界、默认 TTL、最大 TTL 必测          |
| R-012    | 所有资源和来源按 owner 隔离                             | 安全设计       | 跨租户读写均不泄露存在性                   |

### 3.4 状态变化与不变量

| 类型       | 说明                                                                           |
| ---------- | ------------------------------------------------------------------------------ |
| 摘要写入   | `version = expected + 1`，插入摘要并推进会话指针；历史行不更新                 |
| 记忆写入   | `CANDIDATE -> CONFIRMED -> REVOKED/EXPIRED`；软删除以 `deletedAt` 立即失效     |
| 权限边界   | 用户只能读取和修改自己的会话、消息、摘要、记忆和来源                           |
| 时间规则   | `expiresAt > now` 才 active；`expiresAt == now` 已失效；时间使用 `timestamptz` |
| 数据不变量 | 摘要版本单调递增；记忆版本单调递增；active 唯一；多步写入全成或全败            |

## 5. 风险分析

| 风险                       | 业务影响                     | 测试策略                      | 优先级 |
| -------------------------- | ---------------------------- | ----------------------------- | ------ |
| 摘要半提交                 | 会话指向不存在摘要或版本漂移 | 真实事务故障注入和回滚后计数  | P0     |
| 租户条件遗漏               | 泄露或篡改他人对话、画像     | 每个读写路径建立双用户负例    | P0     |
| 并发 last-write-wins       | 摘要/记忆丢版本或覆盖纠错    | 双连接并发、CAS、唯一索引验证 | P0     |
| 未确认或敏感记忆进入上下文 | 隐私和错误画像风险           | active 列表与策略负例         | P0     |
| 过期/删除仍可见            | 用户“忘记”请求失效           | 时间边界、删除后即时查询      | P0     |
| 历史被更新                 | 审计链和纠错来源丢失         | 写前后快照/hash 比较          | P1     |
