# 智能体业务测试基线方案-20260805

> 范围：`src/apps/agent` 的会话、工作流、Tool 路由、执行、审计与最终回答。  
> 设计原则：按用户任务和可观察结果重新建立测试基线；既有 spec 不作为正确性或覆盖结论。  
> 状态：🔧 审计中

---

## 1. 目标

回答三个独立问题：

1. 当前 Agent 测试中，多少是内部调用/Mock 断言，多少真正验证用户任务结果？
2. 关键用户任务在模型异常、数据缺失、工具降级时，是否仍能避免虚假结论？
3. 哪些场景需要补为 API→队列→Worker→Tool 审计→回答的回归门禁？

## 2. 用户任务模型

| 场景组 | 用户目标 | 可观察业务结果 |
| --- | --- | --- |
| 单证券研究 | 查询一只股票/指数/基金的数据或信号 | 调用正确的单标的 Tool；数据日期、空值与引用真实 |
| 全市场筛选 | 按板块、信号或条件排名 | Tool 输入覆盖完整目标母体；排序和板块不串样 |
| 数据可用性 | 问覆盖、水位、缺失原因 | 只报告真实库存；不把可用性 Tool 当成业务筛选结果 |
| 私有分析 | 查询组合、自选、回测 | 用户隔离、所有权和点时数据成立 |
| 外部事件研究 | 新闻、公告、事件影响 | 来源受控、结论可追溯、未授权能力不执行 |
| 失败与降级 | 模型、Tool、队列、数据异常 | 显式失败或诚信降级；不以样本、旧数据或空值编造结论 |

## 3. 关键不变量

| 编号 | 不变量 | 验证证据 |
| --- | --- | --- |
| A-001 | 用户问题所需的 Tool 未执行时，回答不能声称完成该分析。 | Run/Tool 审计、回答、引用 |
| A-002 | 路由模型失败不能改变研究母体或放宽筛选条件。 | 计划与 Tool 输入 |
| A-003 | Tool 的数据范围、证券类型、用户归属和时间口径必须与问题一致。 | Tool 输入/输出、数据截止与审计 |
| A-004 | 每个事实性结论必须由相应 Tool 或受控网页来源支撑。 | 引用与 `factId` 映射 |
| A-005 | 超时、取消、并发重试只能产生一个一致终态，不能留下成功外观的半成品。 | Run、Event、Audit 记录 |
| A-006 | 模型输出结构化失败时，恢复逻辑要么完成等价确定性任务，要么显式终止。 | 失败注入 E2E |

## 4. 审计方法

1. 仅从 Agent API、Swagger、前端交互约定、Tool 清单和用户问题推导场景与期望。
2. 文档定稿后扫描所有 Agent spec，标记为：契约、实现导向、业务场景、真实集成或 E2E。
3. 对每个 P0 场景检查是否同时验证：用户输入、Tool 审计输入、Tool 输出边界、最终回答/错误终态。
4. 不把测试数量、Mock 覆盖率或绿灯结果当作业务覆盖结论。

## 6. 首轮自动化审计结果

执行命令：`pnpm exec jest src/apps/agent --runInBand`。结果为 **52 suite / 375 用例通过，7 suite / 73 用例跳过**。

| 观察项 | 证据 | 结论 |
| --- | --- | --- |
| 测试总量 | 59 个 spec、448 个用例（含跳过） | 数量充足，不等于业务链完整。 |
| 实现导向测试 | 34 个 spec 同时含 Mock 设置或 `toHaveBeenCalled` 断言 | 适合保护接口/节点实现，不能单独作为用户结果正确性证据。 |
| 研究工作流真实集成 | `stock-research.integration.spec.ts` 默认跳过，固定 v1、fake model、`0 ToolCall` | 未覆盖 v10 的真实 Tool 路由、筛选、引用和降级。 |
| Stream “E2E” | HTTP 层测试替换了 Stream service | 覆盖协议，不覆盖消息→队列→Worker→Tool→回答链。 |
| 全市场选股 | 原有相关 spec 主要测试 Tool adapter 和 Workflow 版本/节点；未从用户问题验证科创板/创业板精确 Tool 输入 | AGENT-SCREEN-001/002 能穿过既有测试是正常结果。 |

结论：不能据此认定每个既有 Agent 测试都无价值；它们对 DTO、策略、仓储、节点和协议仍有回归价值。但当前测试组合**不足以证明关键用户任务正确**，特别是模型失败、Tool 选择、数据范围、最终回答之间的一致性。

## 7. 后续交付标准

- 每个现有 Agent spec 已分类，并量化实现导向与业务场景测试占比。
- 每个 P0 场景均有缺口结论、证据和补测优先级。
- 至少完成 AGENT-BASE-001 与 AGENT-BASE-005 的可执行回归；其余 P0 形成独立测试计划。
- 缺陷按“业务影响、复现、期望、实际、根因、回归”记录；不以绿灯数量代替结论。
