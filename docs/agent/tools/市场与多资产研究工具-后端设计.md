## 1. 范围

```text

get_fund_research@1

```

本批把研究对象从单只股票扩展到指数、基金、行业、横截面因子和宏观序列。全部读取本地 PostgreSQL 或运行现有确定性计算，不在 Agent 请求内访问 Tushare。

## 3. 模块与依赖

现有业务模块各自新增 Agent Facade 并由原 module export，不在 AgentModule 重复 provide：

```text
IndexModule
  -> IndexResearchRepository
  -> IndexResearchToolFacade

FundModule
  -> FundResearchRepository
  -> FundResearchToolFacade

IndustryRotationModule
  -> IndustryRotationToolFacade

FactorModule
  -> FactorAnalysisToolFacade

MacroResearchModule（新增）
  -> MacroResearchRepository
  -> MacroResearchToolFacade
```

复杂 SQL 放 Repository。Facade 负责 section 编排、时点、限界、错误和 provenance。已有 Service 能满足确定性业务语义时复用；不得复制算法。

## 4. `get_index_market_data@1`

### 4.1 输入

| 字段               | 类型     | 默认           | 约束                                              |
| ------------------ | -------- | -------------- | ------------------------------------------------- |
| `indexCode`        | string   | —              | 必填，`^\d{6}\.(SH\|SZ)$`，必须存在               |
| `sections`         | enum[]   | `QUOTE`        | `BASIC,QUOTE,HISTORY,VALUATION,CONSTITUENTS`；1–5 |
| `asOfDate`         | ISO date | 最近共同 READY | 可选                                              |
| `startDate`        | ISO date | `endDate-1y`   | HISTORY/VALUATION；跨度最多 10 年                 |
| `endDate`          | ISO date | asOfDate       | 不晚于 asOfDate                                   |
| `frequency`        | enum     | `D`            | `D,W,M`；W/M 在 Facade 确定性聚合                 |
| `constituentLimit` | integer  | 100            | 1–500                                             |

### 4.2 输出

```ts
interface IndexMarketData {
  meta: {
    indexCode: string
    name: string | null
    requestedAsOfDate: string | null
    dataThroughBySection: Record<string, string | null>
    coverageStartBySection: Record<string, string | null>
    currency: 'CNY'
    adjustment: 'NONE'
  }
  basic: SectionResult<{
    market: string | null
    publisher: string | null
    category: string | null
    baseDate: string | null
    basePoint: number | null
  }>
  quote: SectionResult<IndexBar | null>
  history: SectionResult<IndexBar[]>
  valuation: SectionResult<
    Array<{
      tradeDate: string
      pe: number | null
      peTtm: number | null
      pb: number | null
      turnoverRate: number | null
      totalMv: number | null
    }>
  >
  constituents: SectionResult<{
    weightDate: string
    total: number
    items: Array<{ tsCode: string; name: string | null; weightPct: number | null }>
  }>
}
```

`IndexBar` 包含 tradeDate、OHLC、preClose、change、pctChg、vol、amount。单位：价格为指数点，pctChg/weight 为百分数，amount 使用源表单位并明确标记。

规则：

- 各 section 独立水位线；权重月末落后日线不算错误。
- CONSTITUENTS 选择不晚于 asOfDate 的最近权重日。
- W/M 使用日线按交易期聚合，算法版本 `index-bar-aggregation.v1`。
- 没有估值时 VALUATION 为 NOT_READY，不影响 HISTORY。

Policy：READ、PUBLIC_MARKET_DATA、20 秒、maxRows 2,500、cost MEDIUM。

## 5. `get_fund_research@1`

### 5.1 输入

| 字段              | 类型     | 默认                  | 约束                                           |
| ----------------- | -------- | --------------------- | ---------------------------------------------- |
| `fundCode`        | string   | —                     | 必填，基金代码，必须由 resolver 确认为 FUND    |
| `sections`        | enum[]   | `BASIC,NAV`           | `BASIC,NAV,PRICE,SHARE,HOLDINGS,ETF_FLOW`；1–6 |
| `asOfDate`        | ISO date | 各 section 最近 READY | 可选                                           |
| `startDate`       | ISO date | `endDate-1y`          | NAV/PRICE/SHARE/ETF_FLOW；最多 10 年           |
| `endDate`         | ISO date | asOfDate              | 可选                                           |
| `holdingPeriods`  | integer  | 4                     | 1–12                                           |
| `maxSeriesPoints` | integer  | 500                   | 20–1,000                                       |

### 5.2 输出

```ts
interface FundResearchData {
  meta: {
    fundCode: string
    name: string | null
    requestedAsOfDate: string | null
    dataThroughBySection: Record<string, string | null>
    coverageStartBySection: Record<string, string | null>
  }
  basic: SectionResult<{
    management: string | null
    custodian: string | null
    fundType: string | null
    foundDate: string | null
    dueDate: string | null
    listDate: string | null
    issueAmount: number | null
    benchmark: string | null
    status: string | null
  }>
  nav: SectionResult<FundNavPoint[]>
  price: SectionResult<FundPricePoint[]>
  share: SectionResult<Array<{ tradeDate: string; fundShare: number | null }>>
  holdings: SectionResult<FundHoldingPeriod[]>
  etfFlow: SectionResult<
    Array<{
      tradeDate: string
      fundShare: number | null
      shareChange: number | null
      estimatedNetFlow: number | null
      close: number | null
      isEstimated: true
      algorithmVersion: 'etf-flow-estimate.v1'
    }>
  >
}
```

规则：

- NAV 原值和累计/复权值分别命名，不能混为市场价格。
- PRICE 只返回交易所行情；场外基金可能 NOT_READY。
- HOLDINGS 按公告可得日过滤，同一报告期取 asOf 时点最新版本。
- ETF_FLOW 是份额变化 × 价格的估算，必须 `isEstimated=true`；不描述为基金公司披露的精确申赎金额。
- 序列超过 `maxSeriesPoints` 使用首尾必留的确定性等距采样，返回 total/returned/sampling/truncated。

Policy：READ、PUBLIC_MARKET_DATA、25 秒、maxRows 3,000、cost MEDIUM。

## 6. `get_industry_rotation@1`

### 6.1 分类口径

v1 固定 `classification=THS`，直接使用现有同花顺板块目录和数据。不得把 THS 名称映射成申万 L1 后仍宣称为同一来源。

申万统一映射完成后发布 v2，增加显式 `classification=SW_L1`；v1 永不改变含义。

### 6.2 输入

| 字段               | 类型      | 默认              | 约束                                                 |
| ------------------ | --------- | ----------------- | ---------------------------------------------------- |
| `sections`         | enum[]    | `RETURN,MOMENTUM` | `RETURN,MOMENTUM,FLOW,VALUATION,HEATMAP,DETAIL`；1–6 |
| `industryCodes`    | string[]  | 全行业            | 最多 20；必须来自 THS 目录                           |
| `asOfDate`         | ISO date  | 最近 READY        | 可选                                                 |
| `periods`          | integer[] | `[5,20,60]`       | 1–5 个，每项 1–120                                   |
| `topN`             | integer   | 20                | 1–50                                                 |
| `heatmapTradeDays` | integer   | 20                | 5–60                                                 |

### 6.3 输出

```ts
interface IndustryRotationData {
  meta: {
    classification: 'THS'
    requestedAsOfDate: string | null
    dataThroughBySection: Record<string, string | null>
    algorithmVersion: string
  }
  returns: SectionResult<IndustryRankingItem[]>
  momentum: SectionResult<IndustryRankingItem[]>
  flow: SectionResult<IndustryFlowItem[]>
  valuation: SectionResult<IndustryValuationItem[]>
  heatmap: SectionResult<IndustryHeatmapCell[]>
  detail: SectionResult<IndustryDetailItem[]>
}
```

每项必须带 industryCode/name、tradeDate、source、样本股票数、核心值、排名。收益、动量、资金和估值的不同数据日分别输出，不能强行取一个伪共同日。

规则：

- 排名固定 `metric DESC, industryCode ASC`。
- `topN` 只限制返回，不改变排名母体。
- 估值汇总必须返回有效样本数和 null 覆盖率。
- HEATMAP 最大 `50 × 60=3,000` cells；超限 Schema 拒绝。

Policy：READ、PUBLIC_MARKET_DATA、30 秒、maxRows 3,000、cost HIGH。

## 7. `get_factor_analysis@1`

### 7.1 安全边界

只允许 `FactorLibraryService` 中状态为启用、来源为内置/预计算的固定 factorName。禁止：

- 自定义 SQL、表达式、函数名、列名。
- `FactorCustomService` 的创建、测试、更新、删除。
- Agent 触发预计算、回补、回测提交或保存策略。

### 7.2 单操作输入

一个调用只执行一个 `analysis`，避免 sections 产生不可判定的交叉参数：

| 字段                | 类型      | 约束                                                     |
| ------------------- | --------- | -------------------------------------------------------- |
| `analysis`          | enum      | `VALUES,IC,QUANTILE,DECAY,DISTRIBUTION,CORRELATION`      |
| `factorNames`       | string[]  | 普通操作恰好 1 个；CORRELATION 2–10 个；全部命中内置目录 |
| `asOfDate`          | ISO date  | VALUES/DISTRIBUTION/CORRELATION 必填或默认 READY         |
| `startDate/endDate` | ISO date  | IC/QUANTILE/DECAY；最大跨度 3 年                         |
| `universe`          | enum      | `ALL,HS300,ZZ500,ZZ1000`，默认 ALL                       |
| `forwardDays`       | integer   | IC 1–60，默认 5                                          |
| `icMethod`          | enum      | `SPEARMAN,PEARSON`，默认 SPEARMAN                        |
| `quantiles`         | integer   | QUANTILE 3–10，默认 5                                    |
| `rebalanceDays`     | integer   | QUANTILE 1–20，默认 5                                    |
| `decayPeriods`      | integer[] | DECAY 1–10 个，每项 1–60                                 |
| `bins`              | integer   | DISTRIBUTION 10–100                                      |
| `page/pageSize`     | integer   | VALUES：page 1–1000；pageSize 10–200                     |

Adapter 根据 `analysis` 严格拒绝缺失或无关字段，不静默忽略影响语义的参数。

### 7.3 输出

```ts
interface FactorAnalysisData {
  analysis: string
  factorDefinitions: Array<{
    name: string
    label: string
    direction: string | null
    unit: string | null
    sourceType: string
    definitionVersion: string
    definitionHash: string
  }>
  universe: string
  requestedAsOfDate: string | null
  dataThrough: string | null
  sampleCount: number
  result:
    | FactorValuesResult
    | FactorIcResult
    | FactorQuantileResult
    | FactorDecayResult
    | FactorDistributionResult
    | FactorCorrelationResult
  algorithmVersion: string
}
```

通用规则：

- 缺失值不填 0；返回 coverage、有效/无效样本数。
- IC 明确 Spearman/Pearson、forwardDays、交易日对齐和置信信息。
- QUANTILE 返回每组样本、收益、换手和 long-short spread。
- CORRELATION 保留 pairwise 样本矩阵和并列秩处理方式。
- 输入因子顺序不决定矩阵轴；输出显式返回实际排序。
- 高成本分析结果可用 `factorName + paramsHash + dataVersion` 缓存 15 分钟；缓存中不存 Tool audit metadata。

Policy：READ、PUBLIC_MARKET_DATA、60 秒、maxRows 5,000、cost HIGH；一次 Run 最多 3 次。

## 8. `get_macro_snapshot@1`

### 8.1 输入

| 字段           | 类型    | 默认     | 约束                                            |
| -------------- | ------- | -------- | ----------------------------------------------- |
| `series`       | enum[]  | 全部     | `CPI,PPI,GDP,SHIBOR`；1–4                       |
| `sections`     | enum[]  | `LATEST` | `LATEST,HISTORY`；1–2                           |
| `startPeriod`  | string  | 自动     | CPI/PPI `YYYYMM`、GDP `YYYYQn`、SHIBOR ISO date |
| `endPeriod`    | string  | 最新     | 必须与 series 兼容；多 series 时不得传          |
| `historyLimit` | integer | 60       | 1–500                                           |

多 series + HISTORY 时按每个 series 最近 `historyLimit` 条返回，避免一组 start/end 格式歧义。

### 8.2 输出

```ts
interface MacroObservation {
  period: string
  values: Record<string, number | null>
  officialPublicationDate: null
  systemKnownAt: string
}

interface MacroSnapshotData {
  requestedSeries: string[]
  dataThroughBySeries: Record<string, string | null>
  coverageStartBySeries: Record<string, string | null>
  latest: SectionResult<Record<string, MacroObservation | null>>
  history: SectionResult<Record<string, MacroObservation[]>>
  unitsByField: Record<string, string>
}
```

时点限制：当前四张表没有正式发布日期。`syncedAt` 只能作为系统首次已知时间，不能冒充官方发布日。因此强制：

- `officialPublicationDate=null`。
- warning `OFFICIAL_PUBLICATION_DATE_UNAVAILABLE`。
- Agent 可描述当前/历史观察值，但不得据此断言某历史交易日在官方发布前已经知道该值。
- 需要宏观点时回测时，另行补充可信发布日数据源和 migration，不能使用观察期代替发布日期。

Policy：READ、PUBLIC_MARKET_DATA、10 秒、maxRows 2,000、cost LOW。

## 11. 测试

### 11.1 业务推导

- 指数 W/M OHLC 聚合用固定 5 日/跨月样本手算。
- 基金 NAV、市场价格、份额、估算资金流不混用单位。
- 行业排名同分时稳定，topN 不改变母体排名。
- 因子 IC、分组收益、衰减和相关系数用可手算截面独立验证。
- 宏观 period 格式、单位和 systemKnownAt 行为明确。

### 11.2 安全与性能

- Factor Tool 无法触达 Custom/Expression/Precompute/Backtest 写 Service。
- 五个 Tool 无 Tushare Client/API 依赖。
- 私有 fund/portfolio 数据不混入公共工具。
- 每类大序列均有查询硬上限、采样/分页和 truncated。
- 真实库保存 EXPLAIN，检查无 N+1。

- Agent 调用只访问本地 PostgreSQL 与确定性计算；边界测试禁止 Tushare Client/API/Sync、自定义因子写服务和预计算写入口。

### 13.2 实现口径补充

- 指数 `W/M` 聚合版本为 `index-bar-aggregation.v1`；开高低收、首日昨收、成交量和成交额均由程序聚合。
- ETF 资金流严格标记 `isEstimated=true`，公式为 `份额变化（万份）× 10,000 × 同日收盘价`。
- 行业主分类固定 THS；资金流和估值跨来源只按名称完全匹配，分别返回来源 warning，未匹配项不猜测映射。
- 因子 Tool 仅接受 `isBuiltin=true && isEnabled=true`，按 analysis 拒绝无关字段；Spearman 并列值使用平均秩，分组收益不再把缺失收益填 0。
- 宏观输出固定 `officialPublicationDate=null`，并返回 `OFFICIAL_PUBLICATION_DATE_UNAVAILABLE`。
