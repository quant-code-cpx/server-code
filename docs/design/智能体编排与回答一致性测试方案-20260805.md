## 3. 业务状态与不变量

### 3.1 编排状态

```text
任务约束 = 实体 + 证券类型 + 市场/板块 + 时间/复权 + 数量/排序 + 数据权限 + 用户目标

任何模型恢复、重试、fallback、Tool 降级都只能保持或收紧任务约束，不能静默改变它。
```

### 3.2 四类可接受输出

| 输出类型 | 适用条件                               | 必须包含                      | 禁止                     |
| -------- | -------------------------------------- | ----------------------------- | ------------------------ |
| 完整回答 | 所有必需事实成功且可验证               | 结果、口径、独立水位、引用    | 隐藏缺失或失败           |
| 部分回答 | 可选事实失败，剩余事实仍能支持局部结论 | 明确完成范围、缺口、warning   | 完整排名/完整比较措辞    |
| 澄清问题 | 实体、范围或高成本目标不明确           | 候选或需补充字段              | 猜一个实体继续执行       |
| 受控失败 | 必需事实、权限、引用或数据质量不满足   | 稳定错误、可重试语义、traceId | 用样本/旧值/模型常识补造 |

### 3.3 每个自动化用例的联合断言

1. 规范化任务约束；
2. 必须、允许、禁止 Tool 集合；
3. 每次 Tool 的规范化输入，而非只看调用次数；
4. Tool 结果进入事实账本的范围、来源、asOf、warning；
5. 最终消息中每项事实的引用；
6. Run/Message/Step/Tool/Model/Event 的状态和 attempt；
7. 未发生越权调用、重复费用或写入。

## 7. 性能与压力测试设计

| 项目       | 设计                                                                                              |
| ---------- | ------------------------------------------------------------------------------------------------- |
| 环境       | 本地 Docker PostgreSQL/Redis，独立 agent-worker，模型/搜索使用 fake server                        |
| 数据规模   | 单股、20 股比较、两板全市场筛选；1/3/10/18 Tool 计划；500 行表格/5000 bars 上限                   |
| 预热       | 每场景冷缓存 1 次、热缓存 5 次；负载前 30 秒预热                                                  |
| 并发       | 1/5/10/20/50 用户阶梯；每用户独立会话，30% SSE 重连，10% 取消                                     |
| 指标       | 首事件/终态 p50/p95/p99、Run throughput、队列等待、Tool/模型 bulkhead、DB/Redis、RSS/heap、错误率 |
| 正确性门禁 | 任意压力级别不得出现跨用户数据、双终态、重复写入、sequence 冲突或无引用事实                       |
| 停止条件   | DB pool 打满、错误率连续 1 分钟 >5%、内存不可恢复增长、队列停止回落                               |
| 清理       | 独立测试用户/会话；按 execution/run ID 清理；保留失败审计快照                                     |
