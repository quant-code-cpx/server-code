## 1. 本轮目标

- 长会话达到双阈值时自动生成版本摘要；短会话不产生额外模型成本。
- 当前问题、最近消息和旁支消息不被压缩；摘要事实和来源可回溯。
- 模型/校验失败安全降级；CAS 并发不覆盖历史；用户取消仍终止 Workflow。
- 新摘要在同一 `load_context` 中生效，模型 usage 纳入 Run 预算。

## 2. 业务理解摘要

| 项目     | 结论                                                                                      |
| -------- | ----------------------------------------------------------------------------------------- |
| 业务场景 | 长会话在 Context 构建前自动压缩旧消息，原始消息保持不可变                                 |
| 核心规则 | 至少 8 条且 2,048 token；保护最近 20 条；单批最多 500 条/8,192 token；最多一次 CAS 重算   |
| 关键风险 | 当前问题被吞、摘要幻觉、跨租户来源、并发覆盖、每 Run 重复花费、失败阻断回答               |
| 待澄清   | 非锚点语义真实性仍需后续离线模型评测；当前由严格 provenance 和实体/数字/日期/引号校验兜底 |

## 4. 实现结果

- 新增 `ConversationSummaryGeneratorService`：候选选择、双阈值、增量输入、严格输出校验、锚点回溯、CAS 一次重算和 typed warning。
- 新增 `conversation_summary@1` 发布态 Prompt；发布脚本与 ModelCall 审计支持独立 `promptVersionId/attemptCount`。
- `LoadContextNode` 先摘要、再构建 Context；摘要模型 usage 写回 workflow state；普通失败降级，用户取消向上抛出。
- Repository 只选择 canonical `COMPLETED USER` 与 `ASSISTANT version=1`；SYSTEM/TOOL、失败态和重新生成旁支不进入摘要或 recent context。
- 新增 `AGENT_SUMMARY_ENABLED` 回滚开关及阈值/单批上限配置；不新增公共 API。

## 9. 回归结论

- 原始消息和历史摘要未改写；同会话 CAS 只产生一个新版本。
- 当前触发消息和最近 20 条保留为原始消息；同轮 PLAN manifest 已引用新摘要 ID，未复制摘要正文。
- 短会话 E2E 仍保持 2 次 ModelCall；长会话增加独立 `SUMMARIZE`，顺序为 `SUMMARIZE → PLAN → SYNTHESIZE`。
- 模型/Prompt/Schema 失败不提交摘要且 Run 可继续；用户取消不被吞掉。
- 未发现未修复 P0/P1 缺陷。
