## 3. 已自动化场景

- 主链：内部个股数据研究、审计关联、引用、SSE 与最终消息一致。
- 外部数据安全链：`search_web` 只选源，`fetch_web_page` 使用当前 user/run 绑定 token；外部公告事实只引用 `FETCHED` source，内部/外部日期分别展示。
- 可选联网降级：搜索连续两次 TIMEOUT 后 Run 仍 `COMPLETED`；fetch 不执行，只保留内部引用并明确“联网核验未完成”。
- Prompt Injection：恶意网页 canary、禁用 Tool 名和 metadata URL 不进入模型可见输出；Tool trace 仍严格为 overview/search/fetch，风险 warning 可见并入审计。
- 安全 delta：最终 Markdown 在引用验证和引用落库后，以 UTF-8 不超过 1 KiB 分块写入 `model.delta`；不流出结构化模型 JSON 或未验证草稿。
- 幂等：并发相同请求只创建一个 Run；同幂等键不同 Body 返回 6004。
- 故障：required Tool `DATA_NOT_FOUND`、模型重试耗尽均形成 typed FAILED；不生成答案、引用或成功终态。
- 终态一致：FAILED/CANCELLED Run 同事务终止 assistant 消息，禁止停留 `PENDING`。
- 重放：`Last-Event-ID` 优先于 Body 游标；终态尾游标重连不新增事件；100 个持久事件连续重放 20 次，2000/2000、0 gap。
- REST PERF：create/send/status 各 100 次，p95 分别 `3.65/23.97/2.88 ms`，p99 分别 `4.14/29.77/3.06 ms`，错误率 0。
- SSE PERF：100 事件 replay 的 TTFB p95 `48.39 ms`、完成 p95 `48.49 ms`、吞吐 `2233.25 events/s`。
- LOAD：1/5/10 Run 阶梯 p95 `329.72/364.47/662.00 ms`，10 并发吞吐 `15.10 run/s`；消息、事件、SSE 按 Run/会话隔离，队列和 Outbox 无残留。
- STRESS：低阈值 Token 预算和 Tool 次数分别稳定写入 typed `6018/6019` FAILED；单用户第 4 个 SSE 连接返回 429，释放后可重连；独立运行 448 ms，完整回归中 198 ms。
- Tool 门禁：15 个 canonical Tool 全部穿透真实 schema、adapter、policy、Executor 与 audit；成功结果校验 provenance/单位/时点/warning/引用，失败结果校验 typed error 与 `REJECTED/FAILED` 终态。
- 故障恢复：send 事务中途失败全回滚；最终审计失败禁止成功；Redis 首次 enqueue 失败保留 `RETRY` Outbox；恢复后同 jobId 投递；Worker crash 后新 identity 从 Tool checkpoint 继续；重复 claim 只有一个 owner。
- 前端：刷新恢复、取消后重新生成、sequence gap 恢复、duplicate 去重、malformed fail-closed、富响应和 XSS 局部降级。
- 真实浏览器链：使用独立 PostgreSQL 16、Redis 7、真实登录、NestJS API、BullMQ Worker、`get_stock_overview` 和 POST-SSE，完成普通研究、运行中刷新恢复、SYNTHESIZE 阶段取消后重新生成 3 个场景；逐 Run 校验 Message/Step/Tool/Model/Citation/Event 审计。

## 5. 环境说明

- 所有服务端 E2E 使用临时数据库，测试前完整 `prisma migrate deploy`，结束后删除数据库。
- Agent E2E/STRESS runner 自动启动独立 PostgreSQL 16 容器、随机本机端口和密码，内部再创建 fresh DB；结束强制删除容器，不读取主开发库。
- `test:agent:perf` 默认 `baseline`；正式 gate 需显式设置 `AGENT_PERF_MODE=gate`，并按 REST/RUN/REPLAY 配置 `MAX_P95_MS`、`MAX_P99_MS`、`MIN_RPS`/`MIN_EPS`；`AGENT_PERF_MAX_ERROR_RATE` 独立控制错误率。
- 本轮主开发 PostgreSQL 曾出现磁盘 I/O 卡死；未触碰原数据卷，改用独立 PostgreSQL 16 临时容器完成验证。
- Redis 恢复测试使用独立 Redis 7.4 容器和隔离 BullMQ prefix；测试后删除容器，不触碰主 Redis。
- 真实后端 Playwright 使用独立 PostgreSQL 16 与 Redis 7 临时容器，自动 migration、seed、workflow publish、真实登录和结束清理；不使用 Agent API/SSE route mock。
- 旧业务 E2E runner 每次启动独立 PostgreSQL 16、Redis 7、随机本机端口和完整 migration，结束自动删除容器；未触碰主 PostgreSQL/Redis。
- 前端项目要求 Node.js 20+；本轮使用工作区 Node.js 24.14.0 执行 Playwright、Vitest 和 build。
- ESLint 9 暂以 `ESLINT_USE_FLAT_CONFIG=false` 使用 legacy config；`tsconfig.eslint.json` 覆盖 `src/test/scripts`。`.eslint-baseline.json` 按“文件 + ruleId + severity”冻结 297 个历史分组，不以总数抵消新增问题。
