## 3. 业务理解

### 3.1 业务场景

长会话不能把全部原始消息无限送入模型。每次新 Run 构建上下文前，系统应在历史规模达到阈值时，将当前用户、当前会话、active branch 上一段连续旧消息压缩成可追溯版本摘要。生成失败、输出不可信或并发冲突不能阻断回答；原始消息始终是事实源。

### 3.2 核心业务规则

| 规则编号 | 规则                                                                                                                  | 来源                         | 测试影响                                                  |
| -------- | --------------------------------------------------------------------------------------------------------------------- | ---------------------------- | --------------------------------------------------------- |
| R-001    | 只处理 owner-scoped 当前会话；跨租户资源安全失败                                                                      | 会话与记忆设计 §2/§9         | 所有读取、生成、提交均携带 `userId`                       |
| R-002    | 只压缩 active branch 中连续、`COMPLETED` 的 `USER/ASSISTANT` 旧消息                                                   | 会话与记忆设计 §2/§5         | pending/failed/cancelled、旁支、SYSTEM/TOOL 不进入输入    |
| R-003    | 当前 Run 的触发消息和最近 `AGENT_RECENT_MESSAGE_COUNT` 条消息属于保护窗口                                             | 上下文优先级                 | 当前问题和近期对话不可被摘要吞掉                          |
| R-004    | 候选区间至少 8 条消息，且估算 token 至少 2,048 才触发                                                                 | 本批次冻结的保守默认值       | 短会话、短增量不调用模型；阈值配置化                      |
| R-005    | 新摘要输入只包含当前合法摘要一次和其后的新连续原始消息                                                                | 会话与记忆设计 §5            | 禁止历史摘要链递归展开和无限摘要递归                      |
| R-006    | 模型调用固定 `purpose: SUMMARIZE`，使用专用发布态版本 Prompt                                                          | 模型网关设计 §2/§4；版本规则 | DRAFT/缺失 Prompt 不调用模型、不提交摘要                  |
| R-007    | 输出严格为 `summaryText`、`facts`、`sourceMessageIds`                                                                 | Schema 与可追溯要求          | 多字段、缺字段、类型错、超长均拒绝                        |
| R-008    | 每个 fact 至少引用一个本批次 source message；实体、证券代码、数字、日期、引号内容须能在所引消息中找到                 | 会话与记忆设计 §5            | 幻觉、新数字、错误引用拒绝提交                            |
| R-009    | `sourceMessageIds` 只能来自当前合法摘要来源或本批次实际消息，并按消息顺序去重；不得引用范围外、其他会话或其他用户消息 | 摘要可追溯要求               | 防伪造 provenance 和跨租户污染                            |
| R-010    | 摘要提交使用 expected version CAS；冲突后重读，最多受控重算一次，禁止 last-write-wins                                 | 会话与记忆设计 §9            | 并发只产生单调、不可覆盖的版本                            |
| R-011    | 同一有效消息范围重复触发幂等；历史摘要和原始消息不可更新或删除                                                        | Schema/Batch 019 验收        | 重试不产生重复版本                                        |
| R-012    | 选区时固定 `throughMessageId` 快照；摘要期间到达的新消息不混入本次输入                                                | Batch 019 边缘场景           | 并发新消息留给下一轮                                      |
| R-013    | 模型、Prompt、结构校验、CAS 重算耗尽失败均不阻断 Run                                                                  | 会话与记忆设计 §5/§10        | 返回 typed warning，ContextBuilder 回退合法摘要和原始消息 |
| R-014    | manifest/日志只记录摘要 ID、版本、hash、区间、原因和指标，不记录正文、敏感值或模型原始响应                            | Batch 019 可观测性/安全      | 故障信息脱敏                                              |

### 3.3 状态变化与不变量

| 类型       | 说明                                                                         |
| ---------- | ---------------------------------------------------------------------------- |
| 数据写入   | 校验通过后，创建新不可变摘要并原子推进会话 `currentSummaryId/summaryVersion` |
| 模型审计   | 记录 `SUMMARIZE` 调用、Prompt/model、usage、失败类别；不保存隐藏推理         |
| 权限边界   | conversation、summary、message、run 必须属于同一 `userId`                    |
| 时间边界   | 以选区快照和稳定消息顺序确定范围，不以模型完成时间扩大范围                   |
| 数据不变量 | 原始消息不改；历史摘要不改；版本单调；范围连续；事实可回溯                   |
| 失败策略   | 不提交半成品，不推进 current summary，不阻断 `load_context`                  |

## 4. 内部契约

建议输入：

```ts
type MaybeCompactCommand = {
  userId: number
  conversationId: string
  runId: string
  triggerMessageId: string
  inputTokenBudget: number
}
```

建议结果：

```ts
type MaybeCompactResult =
  | { status: 'CREATED'; summaryId: string; summaryVersion: number }
  | { status: 'SKIPPED'; reason: string }
  | { status: 'WARNING'; code: string }

type RollingSummaryOutput = {
  summaryText: string
  facts: Array<{ text: string; sourceMessageIds: string[] }>
  sourceMessageIds: string[]
}
```

`load_context` 在构建上下文前调用；`WARNING` 只追加脱敏 warning，随后照常构建上下文。
