## 6. 全仓回归说明

`pnpm run test:all` 首轮得到 3685 passed、2 failed、84 skipped，共 3771 tests；进程因既有 open handle 未自然退出。失败位于既有 strategy-api 与 stock.controller mock 场景，隔离强制退出重跑得到 2 suites / 69 tests 全部通过，说明是顺序/隔离问题，不是 News 稳定失败。

本轮没有把这两个非 News 测试改成“强行通过”，也不把跳过用例计为成功。仓库 lint baseline 检查通过，但基线本身仍记录既有 1092 errors / 516 warnings，因此不能宣称全仓 lint 零告警。

当前前端工作树执行 `npm run build` 已完整通过；News 定向 ESLint、89 条测试与 OpenAPI 漂移检查也通过。本轮没有把前端仓库其他模块的用户改动纳入 News 交付范围。

Round 5 已关闭 2 小时 SOAK 与隔离故障恢复。以下项目仍需要真实时间窗口、外部恢复或授权，本轮不能伪造结论：

- 92 条前端 Oracle 中尚未自动化或需要专门环境的剩余覆盖。
- 共享工作区新增的 Agent Model Provider 迁移尚未部署；整体发布前必须由其所属变更完成迁移验收。

因此结论分两层：

- **开发与本地集成：GO**。
- **生产全量发布：NO-GO，直至上述非功能门禁关闭**。

## 8. 启用与回滚边界

- 默认 `NEWS_ENABLED=false`，不会意外开始采集。
- 启用时必须配置至少 32 字节的 `NEWS_CURSOR_SECRET`；Bridge token 也至少 32 字节且不得复用。
- AKShare Bridge 只接受内网 DNS origin，不暴露宿主机端口；GDELT 只允许官方 HTTPS DOC 2.0 地址。
- Provider 可分别由 `NEWS_AKSHARE_BRIDGE_ENABLED`、`NEWS_GDELT_ENABLED` 控制，支持独立关闭。
- 本轮用于全迁移验证的临时 schema 仅含合成数据，验证后已精确删除，不可恢复且不影响 public 数据。
