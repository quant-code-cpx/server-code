## 2. 当前能力与阻塞

### 2.1 回测

已有：

- `get_backtest_result@1`：配置、状态、指标、净值、交易摘要。
- `BacktestMonteCarloService`：可复现 seed 的 bootstrap 模拟。
- `BacktestAttributionService`：Brinson 归因。
- `BacktestCostSensitivityService`：手续费/滑点敏感度。
- ParamSweep、WalkForward、Comparison 的持久化结果读取 Service。

边界：参数扫描创建、WalkForward 创建、Comparison 创建会写库/入队，不允许由只读 Tool 触发。

### 2.2 组合

已有风险 Tool 和组合 Service，但当前 `PortfolioPerformanceService` 用“当前持仓”回算整个历史区间，无法代表历史真实持仓。直接开放会产生前视偏差。

必须先建立不可变持仓事件和每日组合快照，再启用 `get_portfolio_analytics`。

### 2.3 报告

已有 `ResearchReportService` 完整两阶段流程：

1. `POST /agent/reports/save` 传 runId 返回 preview、短期 HMAC confirmationToken。
2. 用户确认后携带 token + clientRequestId，再次 POST；服务校验 user、messageVersion、contentHash、journalHash 和过期时间，幂等保存并入队渲染。

现有 Tool 已定义但默认 disabled，执行阶段由 Policy 返回 `CONFIRMATION_REQUIRED`。本批只需打通前端确认事件和启用门禁，不重写报告持久化。

## 3. 私有数据共同规则

- ownerId 永远使用 `ToolAccessContext.userId`。
- Repository 查询必须在首个条件中包含 owner scope，不能先按 id 查再在内存判断。
- 不存在和不属于当前用户统一映射 `DATA_NOT_FOUND`，防止枚举资源 id。
- Tool 输入不得出现 `userId`、`ownerId`、角色或权限字段。
- provenance 不能泄露其他用户标识。
- 审计记录资源 id、userId hash、Tool pin、input/output hash，不记录持仓完整内容。

## 4. `get_backtest_analytics@1`

### 4.1 输入

```ts
interface GetBacktestAnalyticsInput {
  analyses: Array<
    | 'MONTE_CARLO'
    | 'BRINSON_ATTRIBUTION'
    | 'COST_SENSITIVITY'
    | 'PARAM_SWEEP_RESULT'
    | 'WALK_FORWARD_RESULT'
    | 'COMPARISON_RESULT'
  >
  backtestRunId?: string
  paramSweepId?: string
  walkForwardRunId?: string
  comparisonGroupId?: string
  monteCarlo?: {
    simulations: number
    seed: number
    confidenceLevels?: number[]
    maxSeriesPoints?: number
  }
  attribution?: {
    industryLevel?: 'L1' | 'L2'
    granularity?: 'WEEKLY' | 'MONTHLY'
    benchmarkCode?: '000300.SH' | '000905.SH' | '000852.SH'
  }
  costSensitivity?: {
    commissionRates?: number[]
    slippageBps?: number[]
  }
}
```

JSON Schema 约束：

- `additionalProperties=false`，analyses 1–3、去重。
- MONTE_CARLO/BRINSON/COST 必须有 `backtestRunId`。
- PARAM_SWEEP_RESULT 必须有 `paramSweepId`；只读已存在结果。
- WALK_FORWARD_RESULT 必须有 `walkForwardRunId`；只读已存在结果。
- COMPARISON_RESULT 必须有 `comparisonGroupId`；只读已存在结果。
- `simulations` 100–5,000；`seed` 必填且为 32 位整数，禁止默认 Date.now。
- confidence 1–5 个，每项 0.01–0.99、升序去重。
- commissionRates 1–5 个，每项 0–0.01；slippageBps 1–5 个，每项 0–100；网格最多 25。
- analysis 未请求时对应配置不得出现。

### 4.2 输出

```ts
interface BacktestAnalyticsData {
  ownerScoped: true
  backtestRunId: string | null
  runStatus: string | null
  reproducibility: {
    verified: boolean
    engineVersion: string | null
    dataContractVersion: string | null
    universePolicyVersion: string | null
    financialAsOfPolicyVersion: string | null
    adjustmentPolicyVersion: string | null
    qualityFlags: string[]
  } | null
  monteCarlo: SectionResult<MonteCarloResult>
  brinsonAttribution: SectionResult<BrinsonResult>
  costSensitivity: SectionResult<CostSensitivityResult>
  paramSweepResult: SectionResult<ParamSweepResult>
  walkForwardResult: SectionResult<WalkForwardResult>
  comparisonResult: SectionResult<ComparisonResult>
  partial: boolean
}
```

统一规则：

- 只接受 COMPLETED 的基础回测进行新计算；读取异步结果可以返回 PENDING/PARTIAL 状态。
- 基础回测 reproducibility 未 VERIFIED 时仍可返回，但强制 `BACKTEST_BIAS_UNVERIFIED`。
- 各 analysis fail-soft；全部请求项失败时 Tool 失败。
- MONTE_CARLO 输出 seed、模拟数、分位数、正收益概率、回撤分布和确定性采样后的路径；算法版本 `backtest-monte-carlo.bootstrap.v1`。
- BRINSON 输出配置、配置效应、选择效应、交互效应、按期/行业明细；算法版本固定。
- COST 输出原参数、网格、收益/Sharpe/回撤/总成本变化；不能创建新回测。
- PARAM/WALK_FORWARD/COMPARISON 只调用读取方法，禁止 create/enqueue/delete/cancel。

### 4.3 服务边界

新增 `BacktestAnalyticsToolFacade`：

- 首先以 `(resourceId,userId,deletedAt=null)` 校验 owner。
- 编排现有只读计算/读取 Service。
- 统一错误、section、限界和 provenance。
- 不直接注入 BullMQ Queue。

为避免误注入，定义只读端口：

```ts
export const BACKTEST_ANALYTICS_READ_PORT = Symbol('BACKTEST_ANALYTICS_READ_PORT')

interface BacktestAnalyticsReadPort {
  monteCarlo(...): Promise<unknown>
  brinson(...): Promise<unknown>
  costSensitivity(...): Promise<unknown>
  getParamSweepResult(...): Promise<unknown>
  getWalkForwardResult(...): Promise<unknown>
  getComparisonResult(...): Promise<unknown>
}
```

Adapter 只能注入该 read port/Fascade，不能注入写 Service 或 Queue。

### 4.4 Policy

| 字段       | 值           |
| ---------- | ------------ |
| sideEffect | READ         |
| dataScope  | USER_PRIVATE |
| timeout    | 90 秒        |
| attempts   | 1            |
| maxRows    | 10,000       |
| cost       | HIGH         |

一次 Run 最多调用 2 次。结果缓存 key 必须包含 userId、资源 id、数据/算法版本和参数 hash，TTL 10 分钟；禁止跨用户缓存命中。

model PortfolioHoldingEvent {

  quantity         Int
  avgCost          Decimal  @map("avg_cost") @db.Decimal(20, 4)

上述 id/relation 已按当前 `Portfolio` schema 校准。Migration 必须 expand-first，不修改历史 migration；提交前使用 `prisma format` 和隔离库 fresh migration 验证反向 relation、外键和复合主键。

### 5.2 写入不变量

- `PortfolioService.addHolding/updateHolding/removeHolding/applyBacktest` 在同一事务写当前持仓和不可变 event。
- 每个前端 mutation 提供 `idempotencyKey`；重复 key 返回原结果。
- event 记录 before/after，禁止更新或删除。
- 盘后 Job 按交易日重建 snapshot；算法版本 `portfolio-nav.v1`。
- 暂停日使用最近已知收盘价并返回数据质量标记；上市前/退市后不填成本价代替市价。
- 组合变更后只重算受影响日期起的快照，不全表扫描。

### 5.3 历史迁移

现有 `PortfolioTradeLog` 不保证能完整还原历史持仓。迁移时：

1. 为当前持仓生成 `OPENING_SNAPSHOT` event，effectiveDate=迁移日。
2. `coverageStart=迁移日`。
3. 不伪造迁移日前 NAV。
4. 若某组合经人工/自动审计证明历史日志完整，可单独回放并标记 `BACKFILLED_VERIFIED`。

## 6. `get_portfolio_analytics@1`

### 6.1 输入

| 字段                      | 类型     | 默认                   | 约束                                           |
| ------------------------- | -------- | ---------------------- | ---------------------------------------------- |
| `portfolioId`             | string   | —                      | 必填，最长 32；owner scoped                    |
| `sections`                | enum[]   | `OVERVIEW,PERFORMANCE` | `OVERVIEW,PERFORMANCE,PNL,DRIFT,TRADES`；1–5   |
| `asOfDate`                | ISO date | 最近 snapshot          | 可选                                           |
| `startDate/endDate`       | ISO date | 最近 1 年              | 最大 5 年，不早于 coverageStart                |
| `benchmarkCode`           | enum     | `000300.SH`            | 固定指数白名单                                 |
| `targetWeights`           | object   | —                      | DRIFT 可选；最多 100 个 tsCode，权重和约等于 1 |
| `tradePage/tradePageSize` | integer  | 1/50                   | pageSize 1–100                                 |
| `maxSeriesPoints`         | integer  | 500                    | 20–1,000                                       |

### 6.2 输出

```ts
interface PortfolioAnalyticsData {
  meta: {
    portfolioId: string
    name: string
    coverageStart: string
    requestedAsOfDate: string | null
    dataThrough: string
    benchmarkCode: string
    algorithmVersion: 'portfolio-nav.v1'
    ownerScoped: true
  }
  overview: SectionResult<{
    totalAssets: number
    marketValue: number
    cash: number
    holdingCount: number
    topPositions: Array<{ tsCode: string; name: string | null; weight: number | null }>
  }>
  performance: SectionResult<{
    totalReturn: number | null
    annualizedReturn: number | null
    benchmarkReturn: number | null
    excessReturn: number | null
    volatility: number | null
    maxDrawdown: number | null
    sharpeRatio: number | null
    beta: number | null
    series: Array<{ tradeDate: string; nav: number; benchmarkNav: number | null; drawdown: number | null }>
  }>
  pnl: SectionResult<{
    totalPnl: number | null
    realizedPnl: number | null
    unrealizedPnl: number | null
    dailyPnl: number | null
    byPosition: Array<{ tsCode: string; pnl: number | null; contribution: number | null }>
  }>
  drift: SectionResult<
    Array<{
      tsCode: string
      currentWeight: number | null
      targetWeight: number | null
      drift: number | null
    }>
  >
  trades: SectionResult<{ total: number; page: number; pageSize: number; items: PortfolioTradeItem[] }>
}
```

规则：

- PERFORMANCE 只读 `PortfolioDailySnapshot`，禁止重新使用当前持仓回算历史。
- PNL 的 realized 部分只在 event/交易数据足够时返回，否则 null + `REALIZED_PNL_NOT_AVAILABLE`。
- DRIFT 是只读比较，不生成调仓单，不调用 RebalancePlanService 写路径。
- TRADES 只读 owner scoped event/log，按 occurredAt DESC,id DESC 稳定分页。
- startDate 早于 coverageStart 返回 DATA_NOT_READY，并携带 coverageStart。

### 6.3 Policy

READ、USER_PRIVATE、30 秒、2 attempts、maxRows 3,000、cost HIGH。缓存按 userId+portfolioId 隔离。

## 7. `save_research_report@1` 启用

### 7.1 保持现有两阶段协议

```text
模型提出保存
  -> Tool Policy 返回 CONFIRMATION_REQUIRED
  -> 前端展示“保存报告”操作
  -> POST /agent/reports/save { runId } 获取 preview + confirmationToken
  -> 用户明确确认
  -> POST /agent/reports/save { confirmationToken, clientRequestId, journal? }
  -> 内容 hash/owner/过期/幂等校验
  -> 保存 + 渲染队列
```

Tool 本身不绕过确认执行写入。前端必须使用现有结构化 API，不能把 confirmationToken 交回模型。

### 7.2 启用前门禁

- Run 必须 COMPLETED，最终 assistant message VALID，引用检查通过。
- preview 显示 title、summary、dataAsOf、citation 数、journal 草稿和过期时间。
- confirmationToken 绑定 userId、runId、messageId/version、contentHash、journalHash、expiresAt。
- clientRequestId 用户内幂等；重复确认返回同一 report。
- 内容变化、跨用户、过期、篡改、已删除 Run 拒绝。
- 写操作审计和队列失败恢复通过。
- 前端明确按钮确认；不能用普通聊天“好的”自动视为确认。

### 7.3 Tool/前端事件

保持 ToolError `CONFIRMATION_REQUIRED`，在公开事件中附可安全展示的 `action=OPEN_REPORT_PREVIEW` 和 runId；不附 token。若公共错误结构不支持 action，新增专用 confirmation content block，不能塞入自由文本。

## 10. 测试

### 10.1 权限

- user A 访问 user B 的 portfolio/run/sweep/walk-forward/comparison 全部 DATA_NOT_FOUND。
- id 枚举不泄露资源存在性。
- 缓存不能跨用户。
- 输入包含 userId 被 Schema 拒绝。

### 10.2 回测

- Monte Carlo 固定 seed 重复结果 hash 一致；不同 seed 结果不同。
- 用可手算 NAV 验证分位、回撤和正收益概率。
- Brinson 三效应和总归因独立手算。
- 成本网格用具体交易验证手续费最低收费、卖出印花税和滑点。
- 只读 Tool 无 Queue.add、create、delete、cancel 调用。

### 10.3 组合

- 加仓/减仓/清仓事务同时写 event，失败整体回滚。
- 幂等 key 重放不重复改变持仓。
- 用两只股票、现金、换仓事件手算每日资产/NAV/PnL。
- 停牌使用最近市价并 warning；不能用成本价代替。
- 迁移前区间 DATA_NOT_READY，不伪造历史。
- snapshot 重算结果可复现，算法版本变化不覆盖旧版本审计。

### 10.4 报告确认

- preview 不写数据库。
- 跨用户、过期、篡改、内容变化 token 拒绝。
- clientRequestId 重复只生成一份报告。
- 未点击前端确认按钮时 Tool 无法写入。
- 渲染队列失败后记录可恢复，不丢已确认报告。

### 10.5 P95

| 能力                 |                      P95 |
| -------------------- | -----------------------: |
| 组合常规分析         |                     <2 s |
| 回测成本/归因        |                     <5 s |
| Monte Carlo 5,000 次 | <10 s，Tool timeout 90 s |
| 报告 preview         |                     <1 s |

## 11. 发布与回滚

发布顺序：组合事件账本和 snapshot 先运行观察 → 回测分析灰度 → 组合 Tool 灰度 → 报告写确认最后启用。

回滚：

- 移除两个新只读 key和写 Tool enabled key。
- Workflow 回切 v8。
- 停止 snapshot scheduler，但保留事件/快照数据。
- 不回滚已经确认保存的报告，不删除不可变持仓事件。
- expand-first migration 保留，新代码可不读取新表。

完成定义：私有资源无越权，回测计算可复现，组合历史无前视偏差，报告写入必须真实确认且幂等，回滚不破坏用户数据。
