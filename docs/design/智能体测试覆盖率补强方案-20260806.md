## 3. 业务理解

### 3.1 业务场景

- 用户提交研究问题后，系统应幂等创建消息与 Run，异步执行，并通过 SSE 提供可恢复进度。
- Workflow 只能使用固定版本和已授权 Tool；空数据、超时、模型失败、引用失败必须得到稳定且可解释的终态。
- Run、Message、Step、ToolCall、ModelCall 和 Event 是同一业务事实的不同投影，任何异常或并发都不能使它们互相矛盾。
- 重试创建新 Run/消息版本并保留历史；终态记录不能重新进入运行态。
- 用户只能访问自己的会话、Run、记忆、报告和脱敏 Tool 摘要。

### 3.2 核心业务规则

| 规则编号 | 规则                                                             | 来源              | 测试影响                            |
| -------- | ---------------------------------------------------------------- | ----------------- | ----------------------------------- |
| R-001    | `COMPLETED/FAILED/CANCELLED` 为不可离开的终态                    | Agent 状态模型    | 覆盖迟到结果、重复消费、取消竞态    |
| R-002    | 每次状态转换同时推进 `statusVersion` 并追加对应事件              | Agent 状态模型    | 覆盖 CAS 冲突、事务回滚、事件一致性 |
| R-003    | 同一 `clientRequestId` 相同请求幂等，不同请求冲突                | REST 契约         | 覆盖重复提交与并发提交              |
| R-004    | Provider/Tool 成功事实不得被后续本地预算或审计错误改写           | 审计不变量        | 覆盖“成功调用后本地失败”组合路径    |
| R-005    | 必需 Tool 无数据应受控失败；可选 Tool 无数据应跳过并公开限制     | Orchestrator 契约 | 覆盖空集合绑定与依赖链              |
| R-006    | 最终事实数字必须能由引用支持，失败修复不得引入新事实             | 引用与错误码契约  | 覆盖精度、修复上下文和二次校验      |
| R-007    | `CANCEL_REQUESTED` 后迟到结果只可审计，不能完成 Run              | 状态/SSE 契约     | 覆盖 Tool/Model 迟到结果            |
| R-008    | 同一 Run 的事件 sequence 唯一且严格递增，终态事件最后            | SSE 契约          | 覆盖并行 Tool 与断线恢复            |
| R-009    | Body 不接受 `userId`，资源查询必须按认证用户隔离                 | 安全契约          | 覆盖跨用户枚举与越权                |
| R-010    | API/SSE/日志不得泄露 Prompt、隐藏推理、SQL、密钥和原始供应商错误 | 安全/错误码契约   | 覆盖错误脱敏与 payload 投影         |

### 3.3 状态变化与不变量

| 类型       | 说明                                                                 |
| ---------- | -------------------------------------------------------------------- |
| 数据写入   | 消息、Run、Step、调用审计、事件、引用和终态必须保持一致              |
| 缓存/队列  | DB 成功但入队失败由 outbox/确定性 jobId 补偿；重复消费不得重复副作用 |
| 权限边界   | userId 只来自 JWT；非本人资源与不存在资源外部语义一致                |
| 时间规则   | 取消、模型、Tool 和 Run deadline 使用统一时钟；过期结果不得改变终态  |
| 数据不变量 | 引用 factId 可追溯；Tool/Model attempt 递增；终态事件后无业务事件    |

## 13. 第二阶段补强（2026-08-07）

### 13.1 目标与范围

第二阶段不改变既有业务契约，目标是把 Agent 可执行核心代码覆盖率从 `83.75% / 67.37% / 88.57% / 88.21%` 提升到至少 `85% / 70% / 90% / 90%`。优先测试 Provider 配置与降级、研究报告、Tool Adapter 中可能造成错误路由、敏感信息泄露、错误分类失真和不完整研究结果的分支。

### 13.2 独立业务规则

| 规则编号 | 规则 | 业务依据 | 测试影响 |
| -------- | ---- | -------- | -------- |
| R2-001 | Provider 配置缺失、停用或冲突时必须稳定拒绝，不得静默使用错误模型 | 模型路由与成本边界 | 覆盖空配置、重复默认、禁用部署和版本冲突 |
| R2-002 | Provider 密钥、Authorization、原始请求正文不得出现在 API、错误或日志中 | 安全边界 | 覆盖创建、更新、连通性测试和上游错误脱敏 |
