# 智能体可观测性运行手册

## 1. 范围

本手册覆盖 Agent Run、workflow node、模型、Tool、SSE 与 metadata trace 的 Prometheus 指标，Grafana dashboard、Agent 告警和版本化 fake 评测。指标用于发现延迟、失败、成本、数据时效和质量回退；不承载完整 Prompt、模型正文、Tool 原始输入输出、密钥或持仓。

`/metrics` 是基础设施端点，不带 `/api` 前缀。应用全局前缀必须继续排除 `/metrics`、`/health`、`/ready`。

## 2. 启动与检查

```bash
docker compose --profile agent-worker --profile monitoring up -d
docker compose --profile monitoring up -d --force-recreate prometheus
docker compose ps
curl -fsS http://localhost:3000/health
curl -fsS http://localhost:3000/metrics | grep '^agent_'
curl -fsS http://localhost:9090/-/ready
curl -fsS http://localhost:3001/api/health
```

Prometheus 容器初建后才会读取新增的 rule file mount；新增或调整 `agent-alerts.yml` 后必须 `--force-recreate prometheus`。Grafana 的 `Agent Overview` dashboard 由 `monitoring/grafana/dashboards/agent-overview.json` provision，不在 UI 手改唯一副本。

规则语法检查：

```bash
promtool check rules monitoring/prometheus/agent-alerts.yml
```

## 3. 指标与标签

| 指标族 | 关键标签 | 用途 |
| --- | --- | --- |
| `agent_runs_*`、`agent_workflow_node_*` | workflow、node、status | Run/node 成功率和时延 |
| `agent_model_attempts_*`、`agent_model_duration_*`、`agent_model_ttft_*` | provider、model、purpose、status | 模型失败、延迟和首 token |
| `agent_model_tokens_total`、`agent_model_cost_total` | provider、model、direction/currency/source/estimated | usage 与成本对账 |
| `agent_tool_attempts_*`、`agent_tool_duration_*`、`agent_tool_result_bytes_*`、`agent_tool_data_age_*` | tool、status | Tool 结果、时延、大小和新鲜度 |
| `agent_sse_*` | phase、reason | POST-SSE 连接、重放和背压 |
| `agent_trace_spans_total` | span、status | workflow/node metadata trace 完成状态 |

禁止添加 `userId`、`runId`、`traceId`、URL、原始错误正文、Prompt 或任意请求字段为 Prometheus label。需要定位单个 Run 时查询结构化日志和权威审计表，不能扩大 metric label。

## 4. 成本与 Trace

- provider 返回合法成本时优先使用该值；否则按 `AGENT_MODEL_PRICE_CATALOG` 和 `AGENT_MODEL_PRICE_CATALOG_VERSION` 计算 catalog estimate。
- usage 或价格均不可用时成本为 unknown，不补 0；跨币种不在仪表盘中静默相加。
- 每个 Model attempt 单独写 `AiModelCall` 并单独计量；fallback 不能合并成一个 attempt。
- metadata trace 通过 `AgentTracingService` 记录 workflow/node 名称、受控 status、duration 与 trace/run 关联。日志禁止保存 Prompt、模型全文、Tool payload、网页正文、密钥和持仓。
- `AGENT_OBSERVABILITY_ENABLED=false` 或 `AGENT_OBSERVABILITY_TRACE_SAMPLE_RATE=0` 可停用 metadata span；不会停止核心 Run、审计或 Tool/Model 执行。

## 5. 告警处置

| 告警方向 | 首先确认 | 处置 |
| --- | --- | --- |
| Run/model/tool failure | Grafana 时间窗、`agent_*_total`、结构化日志 errorClass | 确认是否单 provider、单 Tool 或发布后回归；保留审计并按既有 retry/fallback 策略恢复 |
| 模型 TTFT/时延升高 | provider/model/purpose 标签、队列 backlog | 检查供应商健康和网络；必要时禁用故障 provider 或下调路由优先级 |
| 成本突增/unknown | `agent_model_cost_*`、`AiModelCall` usage、price catalog version | 检查重复 attempt 和价格配置；unknown 不可当作免费，先限制预算再修复来源 |
| Tool data age | tool 标签与数据水位 | 检查同步数据实际落库时间；不得把同步日志 SUCCESS 当作数据已就绪 |
| SSE backlog/disconnect | `agent_sse_*`、Worker 状态、事件表 sequence | 检查 tail/replay 延迟、连接上限和 Worker；事件表是权威恢复源 |

先收集 metric 时间范围、受控标签、traceId/runId 与审计 ID，再处理；不要把原始请求、token、Webhook secret 或网页正文贴进告警、工单或 dashboard annotation。

## 6. 评测

本地 fake 回归：

```bash
pnpm run eval:agent -- --provider=fake --suite=mvp
```

数据集 manifest 位于 `test/agent/evaluation-datasets/mvp.json`，hash 覆盖 manifest、金融 golden fixture 与模型 regression fixture。门禁检查金融数值、事实、禁止声明、引用类型、Tool trace、成本和 latency；失败命令非零退出。

管理员 API 均为 POST：

- `/api/agent/admin/evaluations/run`
- `/api/agent/admin/evaluations/status`
- `/api/agent/admin/evaluations/detail`

仅 `ADMIN` 可调用。运行结果冻结 dataset、workflow、prompt、model、provider 与 case hash；接口只返回计数、分数和受控 evidence summary，不返回 Prompt、模型输出、隐藏推理或 Tool 原始 payload。

## 7. 回滚

可先关闭 sampling 或将路由配置只保留已知健康 provider。不要删除 `AiModelCall`、`AiToolCall`、`AiEvaluationRun`、`AiEvaluationResult` 或持久事件来消除告警。dashboard/rule 可以回滚到上一版本；回滚后仍保留审计和评测证据。
