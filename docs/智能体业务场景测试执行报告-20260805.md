## 1. 本轮目标

- 先从用户场景、业务不变量和失败方式重建 Agent 测试，不继承旧 spec 结论。
- 用模型失败、数据空/失败、数量边界、Tool 族、引用事实等组合主动寻找 Bug。
- 对确认缺陷做最小修复，执行目标回归、Agent 全量、构建和 Worker 启动验证。

## 2. 业务理解摘要

| 项目     | 结论                                                                                        |
| -------- | ------------------------------------------------------------------------------------------- |
| 业务场景 | Agent 正确性是“问题→约束→Tool→事实→引用→回答→终态”整链一致，不是某节点被调用。              |
| 核心规则 | 模型失败不能改任务范围；required Tool 不可被无关事实替代；factId 存在不代表任意结论都成立。 |
| 关键风险 | 专业意图串 Tool、真实空集与依赖失败混淆、中文/超限数量改写、模型数字幻觉、跨状态伪成功。    |
| 待澄清   | 双板“前十”是各板前十还是合并前十，产品文案仍需最终冻结；当前沿用各板独立前十。              |

## 11. 最终结论

- 改了什么：重建场景优先测试基线与 80+ 编排用例矩阵；新增/改写 26 条首轮 Oracle；修复 7 类新发现缺陷。
- 如何验证：目标 57/57、Agent 403/403（另 73 跳过）、构建和最终 Worker bootstrap 通过。
- 当前状态：首轮编排正确性明显加强；不能声称整个 Agent 真实 E2E、竞态和性能已完成。
- 运行注意事项：明确意图所需 Tool 未启用时会 fail-closed；required Tool 缺失不再由同层事实兜底。
- 下一轮建议：按基线顺序执行双用户私有数据→Run/Queue/SSE 竞态→真实 v10 E2E→Tool 金融语义→负载压力。
