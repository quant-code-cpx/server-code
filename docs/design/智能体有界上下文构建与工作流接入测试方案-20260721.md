## 3. 业务理解

### 3.1 业务场景

长会话不能把全部历史无限发送给模型。每次 ModelCall 必须从持久化权威数据重新构建有界上下文，保留系统安全规则、当前问题、关键事实来源和用户明确确认的长期约束，同时排除越权、删除、过期、未来时点和敏感原值。

### 3.2 固定上下文契约

上下文段顺序冻结为：

```text
系统/安全规则
→ workflow 与 Prompt 固定版本
→ 当前页面上下文与结构化会话状态
→ 当前版本会话摘要
→ 摘要之后的最近原始消息（当前用户问题固定保留）
→ 当前 Run 已完成的 Tool 结构化摘要与引用
→ 用户明确确认且仍有效的长期记忆
→ token 预算验证
```

同一事实如有重复引用，正文只保留一个受控副本，manifest 可保留多个来源 ID。历史消息和外部文本均是不可信数据，不能改变系统/安全规则。

### 3.3 核心业务规则

| 规则编号 | 规则                                                                                            | 来源                     | 测试影响                                 |
| -------- | ----------------------------------------------------------------------------------------------- | ------------------------ | ---------------------------------------- |
| R-001    | 每次调用按目标预算重新构建，不复用供应商请求对象                                                | 会话与记忆设计、模型网关 | 同一 Run 不同预算产生独立结果            |
| R-002    | 段顺序固定，系统规则和当前用户问题不可丢                                                        | 会话与记忆设计           | 顺序和 pinned 内容为 P0                  |
| R-003    | 超限先裁最旧非当前消息，完整表格/网页/重复 Tool 只留摘要或引用；仍超限报 `AI_CONTEXT_TOO_LARGE` | 会话与记忆设计           | 不允许静默超预算或无限摘要               |
| R-004    | 原始消息不可改写；裁剪以完整消息为边界                                                          | Batch 019                | 不截断正文伪造消息                       |
| R-005    | 摘要必须属于当前会话、hash 合法、范围连续且版本与会话 current 指针一致                          | 摘要契约                 | 损坏/错租户摘要不得进入上下文            |
| R-006    | 摘要缺失或损坏时回退有界原始消息并产生 warning                                                  | 会话与记忆设计           | 回退不阻断可回答请求                     |
| R-007    | 最近消息只能取当前用户会话/活动分支；当前问题只出现一次                                         | 租户与分支契约           | 防越权、防重复 token                     |
| R-008    | 仅完成且可追溯的 Tool 摘要可进入；保留结构化值、单位、`asOf`、citation ID                       | Tool/工作流设计          | 失败/运行中/晚于截止日结果排除           |
| R-009    | 仅未删除、未过期的 `CONFIRMED` 记忆可进入                                                       | Batch 019                | candidate/revoked/expired/deleted 全排除 |
| R-010    | 用户要求旧截止日时，晚于截止日的 Tool 结果和记忆事实排除                                        | 会话与记忆设计           | 防未来函数与时点污染                     |
| R-011    | `pageContext` 仅为提示，资源 ID 必须 owner-scoped                                               | 会话与记忆设计           | 跨租户资源安全失败                       |
| R-012    | manifest 只记录 segment 类型、ID、hash、token、warning，不复制摘要、消息、Tool、记忆敏感值      | Batch 019、安全设计      | 日志与 workflow state 脱敏               |
| R-013    | 预算与 segment token 合计确定性、非负，`total <= budget`                                        | Batch 019                | 可审计、可重复                           |
| R-014    | `load_context` 只负责装载，ModelCall 使用其结构化结果；恢复执行不得重复或污染 state             | 工作流设计               | workflow checkpoint 回归                 |

### 3.4 状态变化与不变量

| 类型       | 说明                                                                                         |
| ---------- | -------------------------------------------------------------------------------------------- |
| 数据写入   | 构建过程不修改原始消息、历史摘要或记忆；只更新本 Run 的 workflow state/checkpoint 与审计引用 |
| 权限边界   | 所有查询携带 `userId` 和 `conversationId`；跨租户 Run、会话、摘要、消息、资源均安全失败      |
| 时间规则   | `expiresAt <= now` 视为过期；截止日比较采用结构化 `asOf/validFrom`，不能用日志生成时间替代   |
| 数据不变量 | 当前问题、系统规则始终存在；manifest 不含原值；上下文不超预算；原始消息不被改写              |

## 8. 性能与压力测试设计

| 项目       | 设计                                                                              |
| ---------- | --------------------------------------------------------------------------------- |
| 环境       | 独立 PostgreSQL 16 容器；不操作主 PostgreSQL/Redis；Node 与机器信息随执行报告记录 |
| 数据规模   | 基准 200 messages/100 memories/50 Tool summaries；压力 2000 messages              |
| 预热方式   | 同 fixture 预热 5 次，不复用业务请求结果                                          |
| 并发模型   | 1 用户串行基准；20 用户恒定并发；阶梯升至首次稳定错误                             |
| 指标       | p50/p95/p99、throughput、错误率、DB query count、heap 增量                        |
| 阈值或基线 | 正确性硬阈值：0 越权、0 超预算、0 原值泄漏；延迟先记录本轮基线                    |
| 停止条件   | OOM、DB 连接耗尽、错误率连续 10 秒高于 5%                                         |
| 数据清理   | 删除独立容器及测试 volume；不触碰主服务数据                                       |
