## 3. 业务规则与不变量

| 编号 | 规则 | 来源 | 测试影响 |
| --- | --- | --- |
| R-001 | 用户请求板块内买入信号排行时，必须执行全样本筛选；抽样个股不能推导“没有符合项”。 | 本轮用户问题 | P0：必须存在 `screen_stocks` 调用或明确失败终态。 |
| R-002 | 科创板、创业板是市场板块；`market` 为精确匹配。`SSE`、`SZSE` 交易所分别含主板，不能代替板块筛选。 | Swagger `StockScreenerQueryDto` | P0：每个请求板块必须传对应 `market`；不得传 `exchange` 或不带板块的筛选。 |
| R-003 | 两个板块同时请求时，两个板块均须独立覆盖，且每个 Tool 调用只查询一个精确板块。 | 用户问题 + R-002 | P0：必须有 `market=科创板` 和 `market=创业板` 两次调用。 |
| R-004 | 路由模型异常只能影响路由，不得悄然把“全市场排行”降级为个股抽样结论。 | 产品诚信要求 | P0：确定性恢复路由或显式失败；不得继续生成无依据排行。 |
| R-005 | 工具输出只含对应板块股票；最终显示条数不得超出用户请求上限。 | 用户问题 | P1：工具审计和最终回答均需校验。 |
