# 智能体通知渠道与可靠投递测试方案-20260722

> 范围：Batch 021 `NotificationChannel`、Delivery outbox、站内信、首个外部渠道、`/api/agent/notification-*`。
> 状态：✅ 已实现；首个外部渠道已确认并实现为签名 HTTPS Webhook。

## 1. 业务规则

- 研究 Run 已完成与 delivery 成功是两个独立事实；渠道失败只能重试 delivery，不能重跑研究。
- 渠道、delivery、attempt 以 PostgreSQL 为权威；WebSocket 只作站内信加速，emit 失败不影响持久通知。
- `(channelId, idempotencyKey)` 必须唯一。provider 已接收但响应丢失时，重试不能造成第二条用户可见消息。
- 用户只能管理自己的 channel/delivery；secret 仅密文落库，所有 API、日志、列表、测试结果均不回显。
- 首批内建渠道是 in-app；外部 adapter 必须经用户确认，禁止普通微信自动化。
