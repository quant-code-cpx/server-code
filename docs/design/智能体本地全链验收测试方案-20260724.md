## 3. 业务理解

### 3.1 业务场景

用户登录本地量化平台后，可以创建研究会话、发送问题、观察可恢复的 Agent Run，查看引用与 Tool 摘要；用户可显式管理模型偏好和长期记忆，将完成的回答二次确认保存为研究报告，并管理站内通知。后台定时研究必须经过权限、数据水位、幂等和版本门禁。

### 3.2 核心业务规则

| 规则编号 | 规则 | 来源 | 测试影响 |
| --- | --- | --- | --- |
| R-001 | 会话、Run、记忆、报告、通知和任务只能由当前 JWT 用户访问 | REST API 设计 | 必测未认证和跨用户隔离 |
| R-002 | 创建消息与 Run 使用 `clientRequestId` 幂等，不能重复产生业务写入 | REST API 设计 | 必测重复提交及并发 |
| R-003 | SSE 事件序号对单 Run 严格递增、可断点重放；断网不等于 Run 失败 | SSE 协议 | 必测重连、去重和终态 |
| R-004 | 手动模型只能选择 `AVAILABLE` 项，变更只影响后续 Run | REST API 设计 | 必测模型目录和会话更新 |
| R-005 | 长期记忆必须由用户显式确认；删除后新 Run 不再使用 | 记忆 API | 必测创建、纠正、删除 |
| R-006 | 报告首次请求只生成预览；确认 token、journal 和 request ID 绑定 | 报告 API | 必测预览不落库、确认幂等 |
| R-007 | 通知失败只重试 delivery，不重跑研究；Secret 永不回显 | 通知 API | 必测站内渠道及响应脱敏 |
| R-008 | 定时研究按 owner、版本、交易日和 watermark 放行，重复触发不得重复执行 | 定时研究工作流 | 必测幂等、CAS 和 defer |
| R-009 | 前端刷新、切换会话和旧异步响应不能复制消息或覆盖当前会话 | Agent 前端设计 | 必测刷新恢复和快速切换 |

### 3.3 状态变化与不变量

| 类型 | 说明 |
| --- | --- |
| 数据写入 | 消息、Run、事件、记忆版本、报告、通知渠道、任务和 execution 均持久化 |
| 缓存/队列/通知 | Redis/BullMQ 只加速执行；数据库状态与 outbox 是权威来源 |
| 权限边界 | Body 不接受权威 `userId`；跨用户资源统一拒绝且不泄露存在性 |
| 时间规则 | 本地业务时区为 `Asia/Shanghai`；定时任务使用 IANA 时区与真实交易日 |
| 数据不变量 | Run 只有一个终态；事件 sequence 唯一递增；幂等键不产生重复资源 |

## 4. 接口契约

| 接口组 | Body/行为 | 鉴权 | 关键断言 |
| --- | --- | --- | --- |
| `POST /api/auth/*` | 登录、刷新、退出 | 按端点 | token 生命周期与本地状态一致 |
| `POST /api/agent/conversations/*` | 创建、列表、详情、消息、模型偏好 | JWT | owner 隔离、严格 Body |
| `POST /api/agent/messages/send` | 会话、内容、能力、幂等 ID | JWT | 原子创建消息与 Run |
| `POST /api/agent/runs/events` | Run 与 sequence 游标 | JWT + SSE | 重放、递增、终态 |
| `POST /api/agent/memories/*` | 显式确认的版本化记忆 | JWT | 无确认拒绝、删除立即生效 |
| `POST /api/agent/reports/*` | 预览、确认、查询、软删除 | JWT | 预览不落库、确认幂等 |
| `POST /api/agent/notification-*/*` | 渠道与投递 | JWT | Secret 不回显、重试不重跑 |
| `POST /api/agent/schedules/*` | 任务、CAS、手动执行、execution | JWT | owner、版本、水位、幂等 |

## 6. 风险分析

| 风险 | 业务影响 | 测试策略 | 优先级 |
| --- | --- | --- | --- |
| 登录成功但 Agent 页面不可用 | 本地主流程阻断 | 浏览器真实登录态与页面冒烟 | P0 |
| Run 入队但 Worker 不消费 | 用户永久等待 | 状态、SSE、进程角色联合验证 | P0 |
| 跨用户资源泄露 | 隐私和安全事故 | 第二用户黑盒请求 | P0 |
| 重连或重复提交复制消息 | 数据污染、重复成本 | 幂等与 SSE 重放用例 | P0 |
| 报告预览直接落库 | 用户未经确认产生记录 | 预览前后列表/数据库一致性 | P0 |
| Secret/Tool payload 泄露 | 敏感信息暴露 | 响应字段和 UI 文本检查 | P0 |
| UI 仅静态可见但 API 失败 | 本地无法使用 | 浏览器 console/network 与真实 API 联调 | P1 |

## 8. 性能与压力测试设计

| 项目 | 设计 |
| --- | --- |
| 环境 | macOS、Node 20、Docker PostgreSQL/Redis、本地开发 Compose |
| 数据规模 | 隔离测试用户与脚本固定数据；不批量修改现有业务数据 |

| 并发模型 | 复用已有 Agent E2E 的并发和 fault cases |
| 指标 | 耗时、错误率、重复资源数、Run 终态、事件 gap |
| 阈值或基线 | 无新 SLA；记录真实观测值并与仓库既有门禁比较 |
| 停止条件 | 数据污染、容器异常、错误率失控或资源持续上升 |
| 数据清理 | 优先使用临时数据库；真实本地数据只做可回滚的小规模 UI 操作 |
